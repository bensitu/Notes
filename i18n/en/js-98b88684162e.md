##### Function scope :id=h-c42d1091df09

Functions can nest, which is common in JS, often with anonymous or arrow functions.

```js
function a() {
    function b() {
    }
}
```

Look at this example:

```js
function c() {
    var z = 30;
}

var x = 10;
function a() {
    var y = 20;
    function b() {
        // See note 1 below.
        console.log(x, y);
    }
    b();
}
a();
```

Example explanations:

1. Look here

- Functions define scope boundaries; outside all functions is global scope
- Variable lookup proceeds from inner to outer scopes
  - Finding a variable in an inner scope stops lookup; outer scopes are not searched
  - If no scope contains the variable, an error occurs
- Scope is essentially a function-object property and can be inspected and debugged with console.dir

##### let, var, and scope :id=h-64bea1806abe

If a function references an outer let variable, ordinary outer {} blocks are also scope boundaries, and top-level let occupies a script scope.

```js

    let y = 20;
    function b() {
        console.log(x,y);
    }
    console.dir(b);

```

```js

    var y = 20;
    function b() {
        console.log(x,y);
    }
    console.dir(b);
}
```

Two var declarations with the same name are treated as the same variable in the same scope.

```js

    var e = 20;

console.log(e);		// See note 2 below.
```

Example explanations:

1. Prints 20
2. Still prints 20 because it is the same variable

With let, they are treated as two variables in two scopes

```js
console.log(e);		// See note 2 below.
```

Example explanations:

1. Prints 20
2. Prints 10

##### Feature: function-based prototype inheritance :id=h-8b6bd0881eda

For convenience, JS also provides function-based prototype inheritance.

> **Function responsibilities**
>
> 1. Creates child objects and supplies properties and methods, functioning like a constructor
>
> 2. A function has a special prototype property: the parent of child objects created by the function.
>
>    \*\*Note!\*\* The names differ; this property's role is to supply the prototype for new objects.

```js
function cons(f2) {
    // See note 1 below.
    this.f2 = f2;
    this.m2 = function () {
        console.log("子方法");
    }
}
// See note 2 below.
cons.prototype.f1 = "父属性";
cons.prototype.m1 = function() {
    console.log("父方法");
}
```

Example explanations:

1. Create a child object (this) and supply its properties and methods
2. cons.prototype is the parent object

Use the new keyword to create child objects

```js
let son = new cons("子属性")
```

The child's `__proto__` is the function's `prototype` property

##### JSON :id=h-34ed8f5957ff

When discussing HTTP request formats, we introduced JSON, whose syntax looks very similar to JS objects, for example:

A JSON object can look like this:

```json
{
    "name":"张三",
    "age":18
}
```

A JS object looks like this:

```js
const student = {
    name:"张三",
    age:18
};
```

What are the differences? Here are the main points:

1. Different nature
   - A JSON object is essentially a string used as a data format between client and server; its properties only appear to be object properties.
   - A JS object is an actual object with properties and methods
2. Different syntax details
   - JSON allows only null, true|false, numbers, strings (double quotes only), objects, and arrays.
   - JSON cannot contain other JS object features, such as methods.
   - JSON property names must be enclosed in double quotes

#### 4) Fetch API :id=h-730520e324a2

Fetch API retrieves remote data and always expresses asynchronous results as Promises. Use await or then to receive results. await pauses only the current async function; it does not turn networking into a synchronous request.

Format

```js
fetch(url, options) // See note 1 below.
```

Example explanations:

1. Returns a Promise

await syntax

```js
const 结果 = await Promise
// See note 1 below.
```

Example explanations:

1. Subsequent code

- await is available in async functions and in ES modules supporting top-level await. It cannot be used directly at the top level of an ordinary script.
- Subsequent code does not run until the result arrives

Asynchronous approach

```js
const promise = Promise.resolve('done');
promise
    .then(result => { console.log(result); })
// See note 1 below.
```

Example explanations:

1. Subsequent code

- Subsequent code can execute without waiting for the result

Example:

The Express server has a students.json file

```json
[
    { "id": 1, "name": "张三", "sex": "男", "age": 18 },
    { "id": 2, "name": "李四", "sex": "女", "age": 17 }
]
```

Now retrieve this data using the Fetch API and display it

await syntax

```html
<script>
    async function findStudents() {
        try {
            // See note 1 below.
            const resp = await fetch('students.json')

            // See note 2 below.
            const array = await resp.json();

            // See note 3 below.
            const tp = document.getElementById("tp");
            const row = tp.content;
            const [c1,c2,c3,c4] = row.querySelectorAll(".col");
            const tbody = document.querySelector('.tbody');
            for(const {id,name,sex,age} of array) {
                c1.textContent = id;
                c2.textContent = name;
                c3.textContent = sex;
                c4.textContent = age;
                // See note 4 below.
                const newRow = document.importNode(row, true);
                // See note 5 below.
                tbody.appendChild(newRow);
            }
        } catch (e) {
            console.log(e);
        }

    }
    findStudents()
</script>
```

Example explanations:

1. Get the response object
2. Get the response body and parse JSON into a JS array
3. Display data
4. Clone an element
5. Establish parent-child relationships

- fetch('students.json') sends a request internally, but the response is not immediately available, so await waits for it.
- resp.json() also cannot return the result immediately: it returns a Promise too, so use await to get the result.

Asynchronous approach

```html
<script>
    fetch('students.json')
        .then( resp => resp.json() )
        .then( array => {
            // See note 1 below.
            const tp = document.getElementById("tp");
            const row = tp.content;
            const [c1,c2,c3,c4] = row.querySelectorAll(".col");
            const tbody = document.querySelector('.tbody');
            for(const {id,name,sex,age} of array) {
                c1.textContent = id;
                c2.textContent = name;
                c3.textContent = sex;
                c4.textContent = age;
                // See note 2 below.
                const newRow = document.importNode(row, true);
                // See note 3 below.
                tbody.appendChild(newRow);
            }
        })
        .catch( e => console.log(e) )


</script>
```

Example explanations:

1. Display data
2. Clone an element
3. Establish parent-child relationships

- The first then invokes its arrow function after the response arrives; the argument resp is the response object.
- The second then invokes its arrow function after JSON parsing finishes; the argument is the parsed result, an array in this example.
- Each then returns a new Promise. Returning a plain value passes it to the next then; returning a Promise waits for its result; throwing an exception leads to a later catch.

##### Cross-origin issues :id=h-ec726fb36d84

![image-20220814105448882](Resources/image-20220814105448882.png)

- Any difference in protocol, host, or port makes origins different, for example:
  - <http://localhost:7070/a> and <https://localhost:7070/b> have different origins.
- The browser's same-origin policy also involves page DOM, storage, scripts, and more. CORS lets pages read certain cross-origin responses; fetch and XHR are common uses.
  - Other clients, such as Java HTTP clients and Postman, do not perform same-origin checks.
  - Requests sent through form submissions or direct URL entry in the browser also do not perform same-origin checks.
- For more information, see:
  - [Cross-Origin Resource Sharing (CORS) - HTTP | MDN (mozilla.org)](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CORS)

Solve using request and response headers

![image-20220814144040703](Resources/image-20220814144040703.png)

- A cross-origin fetch request includes an Origin header indicating where the requesting resource originates, allowing the target to identify cross-origin access.
  - In our example, student.html sends fetch and tells Tomcat it originates from localhost:7070.
- The target returns Access-Control-Allow-Origin to tell the browser which origins may use this response.
  - Here Tomcat returns the fetch response, telling the browser that resources from localhost:7070 may use it.

```js
// ...

app.use('/api', createProxyMiddleware({ target: 'http://localhost:8080', changeOrigin: true }));
```
