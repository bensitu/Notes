# Python project engineering: environments, dependencies, checks, and tests :id=h-a42424387beb

Learning objectives: enable another machine to install, check, and run the same project. First learn basic syntax and the command line.

**Scope:** The running project uses Python 3.15, uv 0.13.7, pyproject.toml, uv.lock, Ruff, and pytest. Package versions are locked; readers need not manually assemble the latest dependencies.

## What each project file does :id=h-c24bb1351a20

| File or directory           | Purpose                                                | Commit to version control? |
| --------------------------- | ------------------------------------------------------ | -------------------------- |
| pyproject.toml              | Project metadata, dependencies, and tool configuration | Yes                        |
| uv.lock                     | Resolved dependencies and hashes                       | Yes                        |
| .python-version             | Project interpreter version selection                  | Yes                        |
| .venv                       | Local virtual environment                              | No                         |
| src/task_tools              | Installable Python package                             | Yes                        |
| tests                       | Behavior tests                                         | Yes                        |
| \*.db and cache directories | Local runtime data or tool caches                      | No                         |

Virtual environments isolate Python packages, not automatically databases, OS tools, or service ports. Do not treat .venv as an artifact that can be copied and run on every machine.

## Minimal run instructions :id=h-d2f7f7483c50

First install uv for your machine following its official installation instructions, then:

```powershell
Set-Location examples/taskboard/python
uv --version
uv sync --locked --all-extras
uv run --locked python --version
uv run --locked task-tools sample.csv
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest
```

The first run downloads the required interpreter and dependencies. The expected CSV summary is total=2, completed=1, pending=1. Interpreter downloads require network access; do not delete the lockfile merely because your local python is a different version.

## Adding or upgrading dependencies :id=h-462153bb9a1a

```powershell
uv add package-name
uv add --dev development-tool-name
```

This is a command syntax template: first replace placeholder names with verified real packages. After running it, inspect pyproject.toml and uv.lock, then run checks, tests, and the actual application.

CI uses --locked and fails on inconsistencies; do not repair locks ad hoc in the pipeline. For a deliberate upgrade, update dependencies on a development branch, review changes, then commit both files.

The [project configuration](examples/taskboard/python/pyproject.toml) places cache, messaging, and MongoDB clients in the services extra. Tests include message deduplication, so the unified run instructions use --all-extras. With a smaller installation, explicitly identify unavailable modules and tests.

## Packages, modules, and command-line entry points :id=h-897a4ba327f2

python -m task_tools.cli runs a module; task-tools is the installed entry point generated by project.scripts. Executing internal files directly from an arbitrary directory may break package import paths.

The src layout makes tests behave more like an installed package, rather than incidentally importing a same-named file from the current directory. Do not name your files json.py, typing.py, or other names that may shadow the standard library.

## Tests, formatting, and type checking :id=h-67068220e9f8

Ruff checks obvious errors and selected rules; format standardizes formatting; pytest executes behavioral assertions. They do not prove business correctness and cannot replace one another.

Type annotations do not automatically validate data at runtime. If full static type checking is needed, select and pin a compatible checker separately, then gradually complete third-party types and boundary checks. This example does not claim Ruff passing means type checking passed.

Tests use tmp_path to isolate SQLite and CSV without connecting to production databases. Duplicate-message tests verify database effects, rather than merely asserting a particular printed message.

## Common errors and development quick reference :id=h-e379fdcaf8b8

| Issue                                               | Action                                                                                          |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Package installs but import fails                   | Check the actual interpreter and uv run environment                                             |
| --locked reports an inconsistency                   | After deliberate dependency changes, update the lock in development first; do not bypass checks |
| No wheel for a new Python version                   | Check library support or choose a compatible version; do not compile blindly                    |
| Falls back to copying after cache hard-link failure | Common with caches on another disk; configure link mode as needed                               |
| Deprecation warnings appear                         | Read the source of the warning and plan coordinated upgrades; do not globally suppress warnings |

Requirements files, lockfiles, and build dependencies each serve a purpose. Interpreter, platform, and external services also affect reproducibility. Record these conditions for releases; retaining only pip freeze is insufficient.
