## 1. TypeScript :id=h-ea28e1adacb7

### 1) Problems with dynamic typing :id=h-80cf9d0a4a4d

As discussed earlier, JavaScript is dynamically typed. For example:

```js
function test(obj) {
}
```

obj might just be a string

```js
test('hello, world')
```

obj might also be a function

```js
test(()=>console.log('hello, world'))
```

Uncertainty about obj's type makes later use difficult: an incorrect argument can crash the code.

Dynamic typing means:

- Running the code to see what happens

Static typing means:

- Predicting expected behavior before code runs

The following TypeScript code constrains parameters before execution.

```typescript
function test(msg : string) {
}
```

- Restricts the parameter to string operations

```typescript
function test(msg : Function) {
  msg()
}
```

- Restricts the parameter to function operations

### 2) Getting started :id=h-36077e2fdd05

Install the TypeScript compiler

```cmd
npm install -g typescript
```

Write TypeScript code

```typescript
function hello(msg: string) {
  console.log(msg)
}

hello('hello,world')
```

Run the tsc compilation command

```cmd
tsc xxx.ts
```

Compilation generates JavaScript and erases the types.

```js
function hello(msg) {
    console.log(msg);
}
hello('hello,world');
```

Another example defines a user type with interface.

```ts
interface User {
  name: string,
  age: number
}

function test(u: User): void {
  console.log(u.name)
  console.log(u.age)
}

test({ name: 'zhangs', age: 18 })
```

After compilation

```js
function test(u) {
    console.log(u.name);
    console.log(u.age);
}
test({ name: 'zhangs', age: 18 });
```

TypeScript thus performs compile-time type checking (static typing).

#### Generics :id=h-85543cabb2bd

The following type declarations have obvious similarities.

```typescript
interface RefString {
  value: string
}

interface RefNumber {
  value: number
}

interface RefBoolean {
  value: boolean
}

const r1: RefString = { value: 'hello' }
const r2: RefNumber = { value: 123 }
const r3: RefBoolean = { value: true }
```

They can be improved to:

```typescript
interface Ref<T> {
  value: T
}

const r1: Ref<string> = { value: 'hello' }
const r2: Ref<number> = { value: 123 }
const r3: Ref<boolean> = { value: true }
```

- The key to generics is `<类型参数>`: treat the type itself as a variable factor passed like a parameter, deriving new types with similar structures.

Function definitions also support generics.

```typescript
function ref<T>(n: T): Ref<T> {
  return { value: n }
}

const v1 = ref("hello"); 	// Ref<string>
const v2 = ref(123.3333);	// Ref<number>

v1.value.toLocaleLowerCase()
v2.value.toFixed(2)
```

### 2) Vue components :id=h-76cb835ae962

Vue component files end in .vue, with three sections:

```vue

<template></template>
```

```vue
<template>
```

- Ordinary variables can also appear in templates. To update the page automatically when values change, use reactive APIs such as ref, reactive, or computed.

#### ref and reactive :id=h-9eb73c7ed9cf

Vue provides two functions for making data reactive.

```vue
<script setup lang="ts">
import { ref, reactive } from 'vue'

  <h2>{{msg}}</h2>
```

```vue
</script>

  <h2>{{u1.name}}</h2>

</template>
```

- In templates, ref-wrapped data uses just the variable name.
- In code, ref-wrapped data requires variableName.value.
- reactive-wrapped data is used the same way in templates and code.

#### Computed properties :id=h-e04faa269453

Displaying data sometimes requires simple calculations.

```vue
<script setup lang="ts">
import { ref } from 'vue'
const firstName = ref('三')
const lastName = ref('张')

</script>

<template>
  <h2>{{lastName + firstName}}</h2>
  <h3>{{lastName + firstName}}</h3>
  <h4>{{lastName + firstName}}</h4>
</template>
```

This looks cumbersome; improve it with a computed property.

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'
const firstName = ref('三')
const lastName = ref('张')
const fullName = computed(() => {
  console.log('enter')
  return lastName.value + firstName.value
})
</script>

<template>
  <h2>{{fullName}}</h2>
  <h3>{{fullName}}</h3>
  <h4>{{fullName}}</h4>
</template>
```

- fullName is a computed property. It caches its result and recalculates only when firstName or lastName changes.
- A function providing the same behavior does not cache results.

```vue
<script setup lang="ts">
import { ref } from 'vue'
const firstName = ref('三')
const lastName = ref('张')
function fullName() {
  console.log('enter')
  return lastName.value + firstName.value
}
</script>

<template>
  <h2>{{fullName()}}</h2>
  <h3>{{fullName()}}</h3>
  <h4>{{fullName()}}</h4>
</template>
```

#### xhr :id=h-2eb1136dd24e

Browsers have two APIs for communicating with backends, sending requests and receiving responses. We already covered Fetch; the other is XHR, used as follows:

```js
const xhr = new XMLHttpRequest()
xhr.onload = function() {
    console.log(xhr.response)
}
xhr.open('GET', 'http://localhost:8080/api/students')
xhr.responseType = "json"
xhr.send()
```

Although powerful, this API is old and does not directly support Promises, so wrapping it is useful.

```typescript
function get<T>(url: string): Promise<T> {
  return new Promise<T>((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open("GET", url);
    xhr.responseType = "json";
    xhr.timeout = 5000;
    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(xhr.response as T);
      } else {
        reject(new Error("HTTP " + xhr.status));
      }
    };
    xhr.onerror = () => reject(new Error("Network error"));
    xhr.ontimeout = () => reject(new Error("Request timed out"));
    xhr.onabort = () => reject(new Error("Request was cancelled"));
    xhr.send();
  });
}
```

This wrapper handles success, HTTP errors, network errors, timeouts, and cancellation. T provides only compile-time typing; it does not validate the server's JSON structure at runtime. Check response content separately when strict validation is needed.

- Promises suit wrapping asynchronous operations and work with await.
- The Promise constructor takes an executor function, either ordinary or arrow. Its resolve and reject parameters determine the result.
  - Call resolve on success with the result, which becomes the await result.
  - Call reject on failure with the error, which is ultimately caught in catch.
- await waits until resolve or reject is called before continuing.

Call example 1: receive the result with await, without a proxy

```js
try {
  const resp = await get("http://localhost:8080/api/students")
  console.log(resp)
} catch (e) {
  console.error(e)
}
```

Call example 2: through a proxy

```js
try {
  const resp = await get('/api/students')
  console.log(resp)
} catch(e) {
```

```typescript
  baseURL: import.meta.env.VITE_BACKEND_API_BASE_URL,

_axios.interceptors.response.use(
  response => {
    const code = response.data?.code;
    if (code !== undefined && code !== 200) {
      return Promise.reject(new Error(response.data.message ?? "Request failed"));
    }
    return response;
```

#### Watchers :id=h-90e9a95d7838

Watchers add side effects to reactivity, making more behavior reactive.

- Originally: data changes => page updates

- watch: data changes => other updates

```vue

</template>

<script setup lang="ts">
import { ref, watch } from "vue";
function useStorage(name: string) {
  const data = ref(sessionStorage.getItem(name) ?? "");
  watch(data, (newValue) => {
    sessionStorage.setItem(name, newValue);
  });
  return data;
}
const name = useStorage("name");
</script>
```

- localStorage: data remains after the browser closes
- sessionStorage: data lasts during the browser session
