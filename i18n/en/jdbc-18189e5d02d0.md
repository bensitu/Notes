## What is JDBC? :id=h-7fbfee9f1f5b

JDBC is the standard API for accessing relational databases from Java, mainly in the java.sql and javax.sql packages. Database vendors supply JDBC drivers, which Java code calls through standard interfaces. Tools such as MyBatis and JdbcTemplate build on JDBC to handle repetitive work.

Persistence means saving data in storage that can still be read after a restart, such as a database or file. It is not limited to relational databases.

## Environment and practice tables :id=h-8b5a5f36d1cb

The examples use Java 8+, MySQL 8.x, Connector/J 8.x, and InnoDB. Driver versions and database versions are separate: com.mysql.cj.jdbc.Driver is a driver class name. Do not choose the driver package name solely from whether the database is 5.7 or 8.0.

Create the tables in a practice database first. Use your own database account when running the examples, and never commit real passwords to the repository.

```sql
CREATE TABLE account (
    id BIGINT NOT NULL,
    balance DECIMAL(12, 2) NOT NULL,
    PRIMARY KEY (id)
) ENGINE=InnoDB;
INSERT INTO account (id, balance) VALUES (1, 100.00), (2, 20.00);

CREATE TABLE batch_item (
    id BIGINT NOT NULL AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Add the driver dependency in Maven. The pinned version below is only for reproducing this example.

```xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>8.4.0</version>
    <scope>runtime</scope>
</dependency>
```

JDBC 4 drivers can usually register automatically when the driver JAR is on the runtime classpath. Class.forName can help with older drivers or driver-loading diagnostics; it is not required for every connection.

## URL and connection settings :id=h-481c541f140c

The basic form of a JDBC URL is jdbc:subprotocol:subname. Here is a MySQL example:

```properties
url=jdbc:mysql://localhost:3306/study?characterEncoding=UTF-8
user=study_user
password=replace-with-your-local-password
```

Name the file jdbc.properties and put it in src/main/resources. Create the study database and the account beforehand.

The time-zone parameter must match your time-handling requirements; do not always set UTC merely to suppress an error. For SSL errors, inspect certificates and server/client configuration instead of disabling encryption with useSSL=false by default.

File: JDBCUtils.java.

```java
import java.io.IOException;
import java.io.InputStream;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.util.Properties;

public final class JDBCUtils {
    private JDBCUtils() {}

    public static Connection getConnection() throws IOException, SQLException {
        Properties properties = new Properties();
        try (InputStream input = JDBCUtils.class.getResourceAsStream("/jdbc.properties")) {
            if (input == null) {
                throw new IOException("jdbc.properties was not found on the classpath");
            }
            properties.load(input);
        }
        return DriverManager.getConnection(
            properties.getProperty("url"),
            properties.getProperty("user"),
            properties.getProperty("password"));
    }
}
```

This class only demonstrates reading configuration and obtaining a connection. Production applications normally use framework configuration and connection pools; they should not reread the configuration file for each query.

## Inserts, updates, and deletes with PreparedStatement :id=h-87d6af03265c

Use Connection.prepareStatement(sql). Note the method name: prepareStatement.

? marks a data value to bind, and parameter indexes start at 1. Bound values are not interpreted as SQL structure, making this safer than string concatenation. Structural SQL elements such as table names, column names, and sort directions cannot be bound with ?; the application must control them.

File: JdbcOperations.java. The later transaction examples reuse this method.

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public final class JdbcOperations {
    private JdbcOperations() {}

    public static int update(Connection connection, String sql, Object... values)
            throws SQLException {
        try (PreparedStatement statement = connection.prepareStatement(sql)) {
            for (int i = 0; i < values.length; i++) {
                statement.setObject(i + 1, values[i]);
            }
            return statement.executeUpdate();
        }
    }
}
```

executeUpdate returns the number of affected rows, not the generated primary key. The following is a method-body fragment; import BigDecimal and Connection.

```java
try (Connection connection = JDBCUtils.getConnection()) {
    int rows = JdbcOperations.update(connection,
        "UPDATE account SET balance = ? WHERE id = ?",
        new BigDecimal("120.00"), 1L);
    System.out.println(rows);
}
```

| Method             | Common use                                     | Return value                                                                 |
| ------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| executeQuery()     | SELECT queries                                 | ResultSet                                                                    |
| executeUpdate()    | INSERT, UPDATE, DELETE, and similar statements | Number of affected rows; 0 for some other statements                         |
| execute()          | Unknown result type or multiple results        | Whether the first result is a ResultSet, not whether the operation succeeded |
| getGeneratedKeys() | Retrieving generated keys                      | Returns a result set of generated keys when supported by the driver          |

## ResultSet and query mapping :id=h-355abe3f8515

A ResultSet cursor starts before the first row. next() advances it to the next row and returns true if that row exists.

```java
try (Connection connection = JDBCUtils.getConnection();
     PreparedStatement statement = connection.prepareStatement(
         "SELECT id, balance AS available_balance FROM account WHERE id = ?")) {
    statement.setLong(1, 1L);
    try (ResultSet result = statement.executeQuery()) {
        if (result.next()) {
            long id = result.getLong("id");
            BigDecimal balance = result.getBigDecimal("available_balance");
            System.out.println(id + ": " + balance);
        }
    }
}
```

Put this fragment inside a method. Import java.sql.Connection, PreparedStatement, ResultSet, and java.math.BigDecimal, and handle or declare IOException and SQLException.

| Java type                                   | Common JDBC / SQL equivalents                                                                       |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| int / Integer                               | INTEGER                                                                                             |
| long / Long                                 | BIGINT                                                                                              |
| BigDecimal                                  | DECIMAL / NUMERIC                                                                                   |
| String                                      | CHAR / VARCHAR / text                                                                               |
| byte\[]                                     | Binary columns                                                                                      |
| java.sql.Date                               | DATE                                                                                                |
| java.sql.Time                               | TIME                                                                                                |
| java.sql.Timestamp                          | TIMESTAMP                                                                                           |
| LocalDate, LocalDateTime, and similar types | JDBC 4.2 supports conversion to and from driver-supported date types through getObject / setObject. |

SQL NULL is not the Java number 0. Methods such as getInt and getLong may return 0 when reading NULL, so check wasNull(). Alternatively, use an appropriate getObject overload to obtain a wrapper type.

ResultSetMetaData describes columns: getColumnCount returns their count, getColumnLabel returns the alias or column label, and getColumnName returns the original column name.

Assigning object fields automatically with reflection also requires handling aliases, inherited properties, nulls, and type conversion. Combining getDeclaredField with field.set alone does not make a universal Mapper for every query. Begin by mapping each column explicitly, then use a mature framework.

## Releasing resources and handling errors :id=h-58201f82357d

try-with-resources closes resources when the block ends and attempts to close them even if an exception occurs. The nested form above closes ResultSet first, then PreparedStatement, and finally Connection.

Do not merely print a database exception and return null or 0: callers may mistake a failed operation for no records or no changes. Propagate SQLException to the transaction boundary or a clearly defined error-handling layer.

## Batch writes :id=h-39fe37086f3f

PreparedStatement.addBatch() records the current parameter values, and executeBatch() executes the recorded batch. A regular Statement's addBatch(String) accepts SQL text; do not confuse these methods.

Setting rewriteBatchedStatements=true in Connector/J enables a driver-level batch optimization; it does not turn on batch processing in the MySQL server. Append the option with & if the URL already has parameters, or ? if it has none.

File: BatchExample.java.

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public class BatchExample {
    public static void main(String[] args) throws Exception {
        try (Connection connection = JDBCUtils.getConnection()) {
            connection.setAutoCommit(false);
            try (PreparedStatement statement = connection.prepareStatement(
                    "INSERT INTO batch_item (name) VALUES (?)")) {
                for (int i = 1; i <= 23; i++) {
                    statement.setString(1, "item-" + i);
                    statement.addBatch();
                    if (i % 10 == 0) {
                        statement.executeBatch();
                        statement.clearBatch();
                    }
                }
                statement.executeBatch();
                statement.clearBatch();
                connection.commit();
            } catch (SQLException | RuntimeException exception) {
                try {
                    connection.rollback();
                } catch (SQLException rollbackFailure) {
                    exception.addSuppressed(rollbackFailure);
                }
                throw exception;
            }
        }
    }
}
```

Execute every 10 records, then execute the remaining 3 so that a partial batch is not lost. Executing a batch and committing a transaction are separate operations: the example executes several batches before committing them together.

## A transaction: operations succeed or fail together :id=h-fc8786baceed

A new JDBC connection uses auto-commit by default. After setAutoCommit(false), explicitly commit or roll back. Do not rely on close to commit automatically; behavior when closing with an active transaction depends on the driver implementation.

All SQL in one local transaction must use the same Connection. A DAO must not obtain another connection midway or close a connection borrowed from its caller.

The following transfer example uses BigDecimal for monetary amounts. The preceding SQL creates the two account records.

File: TransferExample.java.

```java
import java.math.BigDecimal;
import java.sql.Connection;
import java.sql.SQLException;

public class TransferExample {
    public static void transfer(long fromId, long toId, BigDecimal amount)
            throws Exception {
        if (fromId == toId || amount == null || amount.signum() <= 0) {
            throw new IllegalArgumentException("Invalid transfer");
        }
        try (Connection connection = JDBCUtils.getConnection()) {
            connection.setAutoCommit(false);
            try {
                int debited = JdbcOperations.update(connection,
                    "UPDATE account SET balance = balance - ? " +
                    "WHERE id = ? AND balance >= ?",
                    amount, fromId, amount);
                if (debited != 1) {
                    throw new SQLException("Source account is missing or funds are insufficient");
                }
                int credited = JdbcOperations.update(connection,
                    "UPDATE account SET balance = balance + ? WHERE id = ?",
                    amount, toId);
                if (credited != 1) {
                    throw new SQLException("Destination account is missing");
                }
                connection.commit();
            } catch (SQLException | RuntimeException exception) {
                try {
                    connection.rollback();
                } catch (SQLException rollbackFailure) {
                    exception.addSuppressed(rollbackFailure);
                }
                throw exception;
            }
        }
    }

    public static void main(String[] args) throws Exception {
        transfer(1L, 2L, new BigDecimal("10.00"));
    }
}
```

The debit condition checks the balance to prevent a negative balance. A failed credit throws an exception and rolls back the debit. Concurrent transfers in opposite directions can still deadlock, causing the database to fail one transaction. Design bounded retries and idempotency around the entire transaction, rather than retrying one UPDATE statement alone.

This example obtains and closes its own connection. When a utility borrows an external connection, the caller manages the transaction and connection state. With a pool, commit or roll back first, then restore state according to the pool's contract. setAutoCommit(true) can itself commit an unfinished transaction and is not a substitute for rollback.

## Responsibilities of a DAO :id=h-6385f9c5741c

A DAO encapsulates database access, not business logic. Start with a clear interface:

```java
public interface AccountDao {
    int debit(Connection connection, long id, BigDecimal amount) throws SQLException;
    int credit(Connection connection, long id, BigDecimal amount) throws SQLException;
}
```

This is an interface fragment. Import the appropriate java.sql and java.math types. The Service passes the connection from its transaction boundary, and both calls use that same connection.

A query with no results can return Optional or an empty collection; failed database access should throw an exception. Do not use the same null to mean both no data and an execution error.

## DataSource and connection pools :id=h-bfc9bca6015b

DataSource is the standard interface for obtaining connections; not every implementation includes a pool. A connection pool reuses physical connections to reduce the cost of opening them repeatedly.

```java
try (Connection connection = dataSource.getConnection()) {
    // Execute database work with this connection.
}
```

Configure dataSource when the application starts. For a pooled connection, close normally returns the connection to the pool. Close the pool itself when the application stops. Do not create a new pool for each request.

| Implementation | What to check when maintaining a project                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| HikariCP       | Common default pool for the Spring Boot JDBC starter; let Boot manage its version and configuration                       |
| Druid          | Use a starter compatible with the project's Boot major version; do not copy configuration from another version unchanged. |
| Apache DBCP 2  | Uses package org.apache.commons.dbcp2, unlike the older DBCP 1                                                            |
| C3P0           | Common in older projects; consult configuration for the installed version                                                 |

An application can have several DataSource instances, for example to connect to two databases. A common setup with one data source is not a rule requiring exactly one.

## Apache Commons DbUtils :id=h-d6e6f723b6e5

DbUtils further wraps JDBC parameter binding and result handling. QueryRunner executes SQL, while ResultSetHandler determines how results are mapped.

| Handler                         | Result                                                    |
| ------------------------------- | --------------------------------------------------------- |
| ArrayHandler / ArrayListHandler | An array for one row / a list of arrays for multiple rows |
| BeanHandler / BeanListHandler   | One JavaBean / a list of Beans                            |
| MapHandler / MapListHandler     | A Map for one row / a list of Maps for multiple rows      |
| ColumnListHandler               | A list of values from one column                          |
| ScalarHandler                   | A single value, such as COUNT(\*)                         |
| KeyedHandler                    | Organizes row Maps using a specified column as the key    |

Within a transaction, use the QueryRunner overload that takes a Connection. Do not switch to an overload that obtains its own connection within the same transaction. Bean mapping still requires matching column labels and property names.

References: [Connection API](https://docs.oracle.com/en/java/javase/17/docs/api/java.sql/java/sql/Connection.html), [Connector/J batch optimization](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-performance-extensions.html), and [DbUtils](https://commons.apache.org/proper/commons-dbutils/).
