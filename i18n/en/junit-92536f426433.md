## Tests: define expectations, then compare results :id=h-a7143108799a

A unit test checks a small unit of code. Assertions compare the actual and expected results; a mismatch makes the test fail. Printing a result alone does not verify it.

Black-box tests are designed from external behavior; white-box tests are designed from internal structure. Both can be automated. JUnit does not require a test to belong to either category.

## JUnit 4 example :id=h-62e3a62af705

For maintaining JUnit 4 projects. JUnit Jupiter uses different packages; do not mix org.junit.Test and org.junit.jupiter.api.Test.

File: src/main/java/example/Calculator.java.

```java
package example;

public class Calculator {
    public int add(int left, int right) { return left + right; }
    public int subtract(int left, int right) { return left - right; }
}
```

File: src/test/java/example/CalculatorTest.java.

```java
package example;

import org.junit.After;
import org.junit.Before;
import org.junit.Test;
import static org.junit.Assert.assertEquals;

public class CalculatorTest {
    private Calculator calculator;

    @Before
    public void setUp() { calculator = new Calculator(); }

    @After
    public void tearDown() { calculator = null; }

    @Test
    public void addsTwoNumbers() { assertEquals(3, calculator.add(1, 2)); }

    @Test
    public void subtractsTwoNumbers() {
        assertEquals(-1, calculator.subtract(1, 2));
    }
}
```

@Before runs before each test method; @After runs after each one. Use @BeforeClass and @AfterClass for setup and cleanup that run once per test class. Their methods must be public static void.

Add the following dependency to dependencies in the POM, then run mvn test.

```xml
<dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>4.13.2</version>
    <scope>test</scope>
</dependency>
```

On failure, inspect the failing test and its expected and actual values first. Do not depend on test-method execution order.

## JUnit Jupiter comparison :id=h-a3d697cc833b

| JUnit 4                    | JUnit Jupiter            | When it runs                                |
| -------------------------- | ------------------------ | ------------------------------------------- |
| @Test                      | @Test                    | Declares a test method; the package differs |
| @Before / @After           | @BeforeEach / @AfterEach | Before / after each test                    |
| @BeforeClass / @AfterClass | @BeforeAll / @AfterAll   | Before / after the entire test class        |
| Assert.assertEquals        | Assertions.assertEquals  | Compares expected and actual values         |

A Spring Boot project uses its managed spring-boot-starter-test and test-framework versions. A plain Maven project also needs a Surefire plugin that can run Jupiter; replacing annotations alone is insufficient.

## Reflection: inspect and invoke classes at runtime :id=h-ccd9f13e9c1d

Reflection can inspect constructors, fields, and methods at runtime. Frameworks often use it to create objects or populate properties.

```java
Class<?> byName = Class.forName("example.Calculator");
Class<Calculator> byType = Calculator.class;
Calculator calculator = new Calculator();
Class<?> byObject = calculator.getClass();

Object instance = byName.getDeclaredConstructor().newInstance();
Object result = byName.getMethod("add", int.class, int.class)
                        .invoke(instance, 1, 2);
```

Put the fragment inside a method and handle or declare reflection-related exceptions. The name passed to Class.forName includes the package. getClass() returns the actual runtime type of an object. This fragment also needs the Calculator class shown earlier.

Member access is restricted by access permissions and module boundaries. Do not pass arbitrary class or method names from external input directly to reflective calls.

## Annotations: information for tools :id=h-873bc94573d7

Annotations are metadata. They do not execute business logic on their own; a compiler, tool, or framework must read and process them.

- @Override: the compiler checks that the method overrides a superclass or interface method.
- @Test: the test framework recognizes a test method.
- @Controller: Spring recognizes a controller.

For a custom annotation, @Target limits where it can be used, and @Retention determines how long it is retained. An annotation read through reflection at runtime needs RetentionPolicy.RUNTIME.

References: [JUnit 4 API](https://junit.org/junit4/javadoc/latest/), [JUnit documentation](https://docs.junit.org/), and the [reflection tutorial](https://docs.oracle.com/javase/tutorial/reflect/).
