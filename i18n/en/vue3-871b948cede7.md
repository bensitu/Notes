# Vue 3 project engineering :id=h-82f546a01a3a

Learning objectives: progress from a single component to a testable, buildable project. First read HTML, JavaScript, asynchronous requests, and the existing Vue 3 notes.

**Scope:** The example uses Node 24, Vue 3, Vite 8, Router 5, and Pinia 4. See package.json and package-lock.json for exact versions and the complete dependency tree. TypeScript is pinned to 5.9.3 to match the verified vue-tsc toolchain.

| File             | Responsibility                                         |
| ---------------- | ------------------------------------------------------ |
| src/main.ts      | Create the application and register routing and Pinia  |

## Minimal run instructions :id=h-33a542671c4f

Start the backend following the [project instructions](examples/taskboard/README.md), then run from the repository root:

```powershell
Set-Location examples/taskboard/frontend
npm ci
npm run dev
```

Open the local address displayed in the terminal. Log in with admin and the backend's APP_PASSWORD. Adding a task should update the list; clicking Complete should change its state.

```powershell
npm test
npm run build
```

build runs both Vue type checking and a production build. Successful development-server startup does not mean type checking passed.

## Reactivity and component responsibilities :id=h-5d65b69dddfa

ref holds values that need tracking. Scripts normally access .value; templates automatically unwrap applicable top-level refs. computed expresses derived values; watch runs side effects after changes and does not replace all computed properties.

Parents pass props, and children request changes through events. Directly modifying props, or copying only a reference and then editing, confuses state ownership.

Composables encapsulate reusable stateful behavior, such as search-request cancellation and loading state. Do not pile an entire page into one enormous useEverything function.

## State, requests, and concurrency :id=h-cac42e229892

Pinia manages the task list shared across components; input text and button busy state stay in the page. Memory state disappears on browser refresh and must not be treated as a database.

The example disables buttons during submission to prevent duplicate actions on one page. The server still uses version fields to prevent stale data overwriting newer data. On 409, reload and ask the user to confirm; do not secretly retry forever.

TypeScript types do not validate external JSON. The example treats responses as unknown and checks task fields individually. On parse failure, retain the old list and show an error; do not turn an error into a “successful empty array.”

## Development and production configuration :id=h-f36d7829f4bf

Vite's /api proxy is development-only. The production image serves pages and forwards API through Nginx. Environment variables exposed through VITE\_ enter browser code and must not contain database passwords or private keys.

Routing, Pinia, and UI libraries must match the current Vue major version. Upgrades require verifying the dependency tree, type checks, tests, and build together; the repository does not automatically combine every tool's latest tag into a compatible set.

## Verification and development quick reference :id=h-e112a2a66c9c

| Symptom                                   | What to check                                              |
| ----------------------------------------- | ---------------------------------------------------------- |
| Browser request returns 404               | Check requests use /api and the corresponding proxy exists |
| 401                                       | Check login and whether session cookies were retained      |
| POST 403 after login                      | Check the post-login CSRF token was retrieved again        |
| Refreshing a subpath returns 404          | Check server fallback to the SPA entry point               |
| Build reports a package export-path error | Check tools support the current TypeScript major version   |

Use a stable task ID as key. Add pagination or virtual scrolling only when long lists require it. This example shows only the latest 100 items and does not pretend to implement full pagination.
