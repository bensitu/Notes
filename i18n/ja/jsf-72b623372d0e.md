# JavaServer Faces の基本概念 :id=h-5fdf2673821f

送信後にデータが更新されない問題を避けるため、コンポーネントツリー、6段階のライフサイクル、Bean のスコープを理解します。

**前提知識とバージョン：** JavaBean と HTML の基礎が必要です。本記事では、学習と既存プロジェクトの保守を目的に JSF 2.x の javax の例を使用します。Faces 4 の連携方法は Springboot+JSF+Mybatis.md を参照してください。

**例の使い方：** 全ファイルと実行手順を明示したプロジェクト以外では、コードブロックは各節の独立した断片です。省略箇所や仮の名前を補ってください。誤りと明記した行は問題を説明するためのものです。同じ節にある代替の書き方を組み合わせないでください。

**JSF（JavaServer Faces）** は、Web アプリケーションの開発に使うサーバー側のコンポーネントベースのユーザーインターフェースフレームワークです。豊富な API とタグライブラリからなる、明確に定義されたプログラミングモデルを提供します。本記事では、Facelets を標準のビュー技術として使用する JSF 2.x を説明します。JSF は後に Jakarta Faces に改称されました。ここにある javax の例をそのまま Faces 3/4 のコードとして使用することはできません。Java で実装されています。

JSF API はコンポーネント（`inputText`、`commandButton` など）を提供し、その状態の管理を支援します。また、サーバー側の検証、データ変換、ページ遷移の定義、拡張性、国際化支援、アクセシビリティなども提供します。

JSF タグライブラリは、Web ページにコンポーネントを追加し、サーバー上のオブジェクトと結び付けます。コンポーネントタグを実装するタグハンドラーも含みます。

これらの機能とツールにより、サーバー側のユーザーインターフェースをより明確に構築できます。

**Facelets 技術**

Facelets はオープンソースの Web テンプレートシステムです。JavaServer Faces（JSF）の標準のビューハンドラー技術であり、正しく動作するには妥当な XML 文書を入力する必要があります。Facelets はすべての JSF UI コンポーネントをサポートし、JSF アプリケーションのビュー構築に特化しています。

**AJAX のサポート**

JSF は AJAX を標準でサポートしているため、Web ページを再読み込みせずにアプリケーションのリクエストをサーバーへ送信できます。JSF は AJAX を使用した部分レンダリングもサポートします。

## 1. JSF のライフサイクル :id=h-c6340313e8e2

ライフサイクルとは、Faces リクエストがサーバーに到着してからレスポンスが生成されるまでの処理順序です。ページは、入力欄とボタンを含むフォームなどのコンポーネントツリーで表現されます。このツリーはサーバー側のオブジェクト構造であり、ブラウザー内の DOM とは異なります。

通常のポストバック（同じ Faces フォームの送信）は、一般に次の6段階を経ます。初めてページを開く場合は、主に「ビューの復元」と「レスポンスのレンダリング」が実行され、フォーム送信時の流れに沿った入力検証は行われません。

| 段階                                   | 処理内容                                             | 初学者が覚えておくべき点                                                          |
| ------------------------------------ | ------------------------------------------------ | --------------------------------------------------------------------- |
| 1. ビューの復元（Restore View）              | 新しいビューを作成するか、保存した状態から元のビューを復元する                  | FacesContext は今回のリクエストに対応するものであり、前回のリクエストと同じコンテキストオブジェクトを保持し続けるわけではない |
| 2. リクエスト値の適用（Apply Request Values）   | リクエストパラメーターから送信値を読み取り、コンポーネントに格納する               | この時点では通常まだ文字列であり、Bean に書き込まれたことを意味しない                                 |
| 3. 検証処理（Process Validations）         | データ型を変換し、入力を検証する                                 | 変換や検証に失敗した場合はメッセージを表示し、通常はモデルの更新と業務メソッドを省略する                          |
| 4. モデル値の更新（Update Model Values）      | 有効なコンポーネント値を Bean のプロパティに書き込む                    | 対応する setter など、書き込み可能なプロパティが必要                                        |
| 5. アプリケーションの呼び出し（Invoke Application） | ボタンなどのコンポーネントの action メソッドを実行し、画面遷移を処理する         | 入力が変換と検証を通過してから業務メソッドを実行する                                            |
| 6. レスポンスのレンダリング（Render Response）     | コンポーネントツリーから HTML または部分更新用のレスポンスを生成し、ビューの状態を保存する | ページでは h:message / h:messages を使ってメッセージを表示する                           |

「実行フェーズ」は最初の5段階の総称であり、「レンダリングフェーズ」は第6段階です。レスポンスのレンダリングを2つの異なる処理段階として数えてはいけません。

### 早期終了と部分リクエスト :id=h-ca37c86818bb

- `FacesContext.getCurrentInstance().renderResponse()` を呼び出すと、現在の段階が完了した後、レスポンスのレンダリングへ進みます。「レンダリングを省略する」という意味ではありません。
- `responseComplete()` の呼び出しは、リダイレクトの完了など、アプリケーションがすでにレスポンスを処理したことを示します。Faces は通常のページレスポンスの生成を続行しません。
- 入力コンポーネントに `immediate="true"` を設定すると、その変換と検証がリクエスト値の適用段階へ前倒しされます。コマンドコンポーネントの immediate は action イベントを早い段階で処理させます。この2つの作用を混同したり、immediate で業務上の検証を回避したりしてはいけません。
- Ajax の execute は処理に参加するコンポーネントを、render は更新するコンポーネントを指定します。execute に参加していない入力が Bean に反映済みだと考えてはいけません。

ビューのレンダリングによって Java アプリケーション全体が再コンパイルされたり、すべての Bean が直ちに破棄されたりすることはありません。Bean の寿命はスコープによって決まり、ビューの状態は設定に応じて Faces がクライアント側またはサーバー側に保存します。機密データをページ出力に含めたり、クライアント側の状態を秘密保持の手段にしたりしてはいけません。

## 2. JSF のマネージド Bean :id=h-09b76029a54b

マネージド bean は、プロパティと `getter`、`setter` メソッドを持つ通常の Java クラスです。

マネージド bean のメソッドは、一般に次の機能を実行します。

- コンポーネントのデータの検証
- コンポーネントが発生させたイベントの処理
- アプリケーションが次に遷移するページを決定するための処理
- JSF フレームワークのモデルとしても使用できます。

**JSF のマネージド Bean の例**

次のサンプルコードを見てみましょう。

```java
public class User {
    private String name;
    public String getName() {
        return name;
    }
    public void setName(String name) {
        this.name = name;
    }
}
```

この `bean` は次の方法で使用できます。

- XML ファイルで設定する方法。
- アノテーションを使用する方法。

### 1. XML ファイルによるマネージド Bean の設定 :id=h-bff8b4d5b1f9

次のコードは、JSF のマネージド bean を登録する方法を示します。

```xml
<managed-bean>
    <managed-bean-name>user</managed-bean-name>
    <managed-bean-class>User</managed-bean-class>
    <managed-bean-scope>session</managed-bean-scope>
</managed-bean>
<managed-bean>
  <managed-bean-name>message</managed-bean-name>
  <managed-bean-class>com.yiibai.test.Message</managed-bean-class>
  <managed-bean-scope>request</managed-bean-scope>
</managed-bean>
```

`bean` を xml ファイルで設定するのは古い方法です。この方法では `faces-config.xml` という xml ファイルを作成します。JSF は `bean` を設定するためのタグを提供しています。

上の例では `bean-name`、`bean-class`、`bean-scope` を指定しているため、プロジェクト内からその bean にアクセスできます。

### 2. アノテーションによるマネージド Bean の設定 :id=h-bfeea3e9e9f6

次のコードは、アノテーションで JSF のマネージド bean を登録する方法を示します。

```java
import javax.faces.bean.ManagedBean;
import javax.faces.bean.ManagedProperty;
import javax.faces.bean.RequestScoped;
import java.io.Serializable;

@ManagedBean(name = "user")  // Using ManagedBean annotation
@RequestScoped                             // Using Scope annotation
public class User implements Serializable {
      private static final long serialVersionUID = 1L;

    private String name;
    public String getName() {
        return name;
    }
    public void setName(String name) {
         this.name = name;
    }

      @ManagedProperty(value="#{message}")   // Uing another bean
       private Message message;

      public void setMessage(Message message) {
    this.message = message;
  }
}
```

@ManagedBean は JSF のマネージド Bean を登録します。name を省略した場合、通常は単純クラス名の先頭文字を小文字にします。例えば User は user になります。eager=true が起動時の生成を意味するのは ApplicationScoped の場合だけです。リクエストやセッションなど、ほかのスコープでは必要に応じて生成されます。

上の Message は依存関係の例です。message という Bean を自分で定義して登録し、注入先以上の長さのスコープを指定する必要があります。setMessage の名前は message プロパティに対応させます。JSF 2.3 ではすでに CDI が推奨され、Faces 4 では旧式の ManagedBean が削除されています。この javax.faces.bean アノテーション群は、旧プロジェクトを保守する場合にだけ使用してください。

これはアプリケーション設定リソースファイルを使用する方法の代替であり、マネージド bean の設定作業を減らせます。

`@RequestScoped` アノテーションは管理対象のスコープを指定します。アノテーションにより bean を保存するスコープを定義できます。指定しなければ、リクエストスコープ（RequestScoped）が既定です。

bean クラスには次のスコープを使用できます。

- **アプリケーション（\[@ApplicationScoped]）**：アプリケーションスコープは全ユーザーで共有されます。最初の HTTP リクエスト時、または `@ManagedBean` に `eager = true` を設定した場合は Web アプリケーションの起動時に生成され、Web アプリケーションの終了時に破棄されます。
- **セッション（\[@SessionScoped]）**：セッションスコープは、Web アプリケーション内の複数の HTTP リクエストにわたって存続します。最初の HTTP リクエスト時に生成され、HTTP セッションが無効になった時点で破棄されます。
- **ビュー（\[@ViewScoped]）**：ユーザーが Web アプリケーションの単一ページ（ビュー）を操作するときに生成され、別のビューへ遷移すると破棄されます。
- **リクエスト（\[@RequestScoped]）**：Web アプリケーションの HTTP リクエストごとに生成され、その HTTP リクエストに対応する HTTP レスポンスが完了すると破棄されます。
- **なし（\[@NoneScoped]）**：アプリケーションにスコープを定義しないことを示します。EL の評価時に生成され、EL の評価後に破棄されます。
- **カスタム（\[@CustomScoped]**：ユーザー定義の標準外スコープです。その値は `java.util.Map` として設定する必要があります。カスタムスコープはあまり使用されません。

**@ManagedProperty アノテーション**

JSF はシンプルな静的 依存性の注入（DI）フレームワークです。@ManagedProperty アノテーションは、別のマネージド Bean を注入するためのマネージド bean のプロパティを示します。

### 3. マネージド Bean の即時生成 :id=h-0b4fd06ec113

マネージド `bean` は既定で遅延生成されます。つまり、アプリケーションから要求されたときにだけ bean がインスタンス化されます。

`bean` をあらかじめ強制的にインスタンス化するには、アプリケーション起動時に `bean` を生成し、アプリケーション（`@ApplicationScoped`）スコープに配置します。次の例のように、マネージド bean の `eager` プロパティを `true` に設定してください。

```java
@ManagedBean(eager=true)
```

# JSF のユーザーインターフェースコンポーネント :id=h-4f883595d365

JSF HTML タグライブラリは、データの表示やユーザー入力の受け付けに使う HTML フォームコンポーネントおよび基本的な HTML 要素を表します。JSF フォームは送信時にこのデータをサーバーへ送ります。

これらのタグを使うには、html ノードに次の URI 名前空間を指定します。

```html
<html
   xmlns="http://www.w3.org/1999/xhtml"
   xmlns:h="http://java.sun.com/jsf/html"
>
```

次の表にユーザーインターフェースコンポーネントを示します。

## JSF UI コンポーネントの例 :id=h-040894687a1d

1. ユーザー登録フォームの作成

Index.xhtml

```html
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml"
      xmlns:h="http://xmlns.jcp.org/jsf/html"
      xmlns:f="http://xmlns.jcp.org/jsf/core">
    <h:head>
        <title>用户注册表单</title>
    </h:head>
    <h:body>
        <h:form id="form">
            <table>
                <tr>
                    <td><h:outputLabel for="name-id">用户名：</h:outputLabel></td>

                <tr>

                </tr>
                <tr>
                    <td><h:outputLabel for="password-id">密码：</h:outputLabel></td>

                </tr>

                <tr>
                    <td><h:outputLabel for="gender">性别：</h:outputLabel></td>
                    <td><h:selectOneRadio id="gender" value="#{user.gender}">
                            <f:selectItem itemValue="男" itemLabel="男" />

        </h:form>
```

2. マネージド Bean の作成

User.java

```java
import javax.faces.bean.ManagedBean;
import javax.faces.bean.RequestScoped;

@ManagedBean(name = "user")
@RequestScoped
public class User {
    private String name;
    private String email;
    private String password;
    private String gender;
    private String address;

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }
    public String getGender() { return gender; }
    public void setGender(String gender) { this.gender = gender; }
    public String getAddress() { return address; }
    public void setAddress(String address) { this.address = address; }
}
```

この例は、フォームのバインドと同一リクエスト内のページ遷移だけを示します。ユーザーをデータベースに保存せず、完全な登録機能ではありません。パスワードをページに再表示してはいけません。実際の登録にはサーバー側の検証と、専用のパスワードハッシュ保存処理が必要です。ここではリダイレクトを使っていないため、リクエストスコープのプロパティをレスポンスページでも読み取れます。

# JSF の Web リソース :id=h-0a1f5141f722

JSF の Web リソースとは、Web アプリケーションで正しく表示するために必要なリソースです。画像、スクリプト（JS）ファイル、ユーザーが作成したコンポーネントライブラリなどが含まれます。

JSF は Web リソースを保存する標準的な方法を提供します。次のいずれかの場所に保存できます。

- Web アプリケーションのルートにある resources ディレクトリのサブディレクトリ、つまり `resources/resource-identifier` に保存します。例として `resources/js`、`resources/css` などがあります。
- Web アプリケーションのクラスパスにパッケージ化するリソースは、`META-INF/resources` のサブディレクトリである `META-INF/resources/resource-identifier` に配置する必要があります。この構造を使用して、Web アプリケーションに同梱する JAR ファイルにリソースを格納できます。

JSF（JavaServer Faces）の実行時には、上に挙げたディレクトリの場所を、その順番で検索します。

アプリケーションの構成は次のとおりです。

```
root:project
|--.gitignore
|--.iml
|--pom.xml
|--README.md
|--doc:文档
|   |--images
|   |--tutorial:整理文档
|--src:源文件
|   |--main
|   |    |--java:源文件
|   |    |   |--web:业务逻辑
|   |    |   |--ejb:数据库操作
|   |    |   |--entity:实体
|   |    |--resources:资源文件
|   |    |   |--META-INF
|   |    |   |   |--beans.xml
|   |    |   |   |--persistence.xml:数据库配置
|   |    |--webapp:web应用
|   |    |   |--resources
|   |    |   |   |--images:图片
|   |    |   |   |--css
|   |    |   |   |--js
|   |    |   |--WEB-INF
|   |    |   |   |--web.xml:web应用配置
|   |    |   |   |--faces-config.xml:JSF配置
|   |    |   |--index.xhtml
|   |--test.ejb.test:测试文件
|--target:目标文件
```

## 画像ファイルへのアクセス :id=h-e95b26874d4d

JSF は、Web アプリケーション内の画像ファイルにアクセスするための `<h:graphicImage />` タグを提供します。次の例では、まず resources ディレクトリと `images` というサブフォルダーを作成します。フォルダーを作成したら、次のコードを記述できます。

`<h:graphicImage>` タグは、`hello.gif` という画像が `resources/images`（Web アプリケーションのルートからの相対パス）にあることを指定します。

```html
<h:body>
<h:form id="user-form" enctype="multipart/form-data">
<h:graphicImage value="#{resource['images:hello.gif']}"/>
<h:graphicImage library="images" name="hello.gif"/>
</h:form>
</h:body>
```

このコードでは2通りの方法で画像にアクセスします。1つ目は式言語のリソース配列を使う方法、2つ目は library 属性を指定する方法です。

## CSS ファイルへのアクセス :id=h-774b472c63c7

`<h:outputStylesheet>` タグは、Web アプリケーション内の CSS リソースへのアクセスに使います。resources フォルダー内にサブディレクトリを作成する必要があります。

次の例では、Web ページから `test.css` ファイルにアクセスします。ファイル *index.xhtml* のコードは次のとおりです。

```html
<html xmlns="http://www.w3.org/1999/xhtml"
xmlns:h="http://xmlns.jcp.org/jsf/html">
<h:head>
<title>Web Resources Example</title>
<h:outputStylesheet library="css" name="test.css"/>
</h:head>
<h:body>
<h1>Welcome to The Yiibai JSF!</h1>
</h:body>
</html>
```

ファイル *test.css* のコードは次のとおりです。

```css
h1 {
color: red;
text-align: center;
}
```

## JavaScript ファイルへのアクセス :id=h-00b6258d1850

`<h:outputScript>` タグは、Web アプリケーション内の JavaScript ファイルへのアクセスに使います。

ここではタグを使って JavaScript ファイルにアクセスします。ファイル *index.xhtml* のコードは次のとおりです。

```html
<html xmlns="http://www.w3.org/1999/xhtml"
xmlns:h="http://xmlns.jcp.org/jsf/html">
<h:head>
<title>Web Resources Example</title>
<h:outputScript library="js" name="test.js"/>
</h:head>
<h:body>
</h:body>
</html>
```

ファイル *test.js* のコードは次のとおりです。

```js
window.onload = function(){
    alert("Welcome to The Yiibai JSF!");
}
```
