# JUnit・リフレクション・アノテーション入門 :id=h-4f03476fa34e

再現性のあるテストの書き方を学び、リフレクションとアノテーションの役割を区別します。

**前提知識とバージョン：** Java のクラスとメソッドの基礎が必要です。完全なテスト例は JUnit 4.13.2 を使います。JUnit Jupiter のアノテーションは比較の節で示します。インポートするパッケージを混在させないでください。

**サンプルの使い方：** 全ファイルと実行手順を明示したプロジェクトを除き、各コードブロックは節ごとの独立した断片です。省略部分や仮の名前を補ってください。誤りと示した行は問題の説明用です。同じ節の代替実装を混ぜないでください。

## テスト：期待値を決めて結果と比較する :id=h-a7143108799a

単体テストは、小さな単位のコードを検証します。アサーションで実際の結果と期待値を比較し、一致しなければテストは失敗します。結果を表示するだけでは検証になりません。

ブラックボックステストは外から見える動作、ホワイトボックステストは内部構造を基にケースを設計します。どちらも自動化でき、JUnit がテストの分類を限定するわけではありません。

## JUnit 4 の例 :id=h-62e3a62af705

JUnit 4 のプロジェクトを保守するための例です。JUnit Jupiter はパッケージが異なるため、org.junit.Test と org.junit.jupiter.api.Test を混在させないでください。

ファイル：src/main/java/example/Calculator.java。

```java
package example;

public class Calculator {
    public int add(int left, int right) { return left + right; }
    public int subtract(int left, int right) { return left - right; }
}
```

ファイル：src/test/java/example/CalculatorTest.java。

```java
package example;

import org.junit.After;
import org.junit.Before;
import org.junit.Test;
import static org.junit.Assert.assertEquals;

public class CalculatorTest {
    private Calculator calculator;

    @Before
    public void setUp() { calculator = new Calculator(); }

    @After
    public void tearDown() { calculator = null; }

    @Test
    public void addsTwoNumbers() { assertEquals(3, calculator.add(1, 2)); }

    @Test
    public void subtractsTwoNumbers() {
        assertEquals(-1, calculator.subtract(1, 2));
    }
}
```

@Before は各テストメソッドの前、@After は各テストメソッドの後に実行します。テストクラス全体で 1 回だけ行う準備と後始末には @BeforeClass、@AfterClass を使い、対応するメソッドを public static void にします。

次の依存関係を POM の dependencies に追加し、mvn test を実行します。

```xml
<dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>4.13.2</version>
    <scope>test</scope>
</dependency>
```

失敗したら、まず失敗したケースと期待値・実際の値を確認します。テストメソッドの実行順序に依存しないでください。

## JUnit Jupiter との比較 :id=h-a3d697cc833b

| JUnit 4                    | JUnit Jupiter            | 実行タイミング                |
| -------------------------- | ------------------------ | ---------------------- |
| @Test                      | @Test                    | テストメソッドを宣言する。パッケージが異なる |
| @Before / @After           | @BeforeEach / @AfterEach | 各テストの前後                |
| @BeforeClass / @AfterClass | @BeforeAll / @AfterAll   | テストクラス全体の前後            |
| Assert.assertEquals        | Assertions.assertEquals  | 期待値と実際の値を比較する          |

Spring Boot のプロジェクトでは、Boot が管理する spring-boot-starter-test とテストフレームワークのバージョンを使います。通常の Maven プロジェクトでは、Jupiter を実行できる Surefire プラグインの設定も必要で、アノテーションの変更だけでは足りません。

## リフレクション：実行時にクラスを調べて呼び出す :id=h-ccd9f13e9c1d

リフレクションでは、実行時にコンストラクター、フィールド、メソッドを調べられます。フレームワークでは、オブジェクトの生成やプロパティーの設定によく使われます。

```java
Class<?> byName = Class.forName("example.Calculator");
Class<Calculator> byType = Calculator.class;
Calculator calculator = new Calculator();
Class<?> byObject = calculator.getClass();

Object instance = byName.getDeclaredConstructor().newInstance();
Object result = byName.getMethod("add", int.class, int.class)
                        .invoke(instance, 1, 2);
```

断片はメソッド内に置き、リフレクションに関する例外を処理するか、throws で宣言します。Class.forName に渡す名前にはパッケージ名も含めます。getClass() は、オブジェクトの実際の実行時型を返します。この断片を動かすには、前に示した Calculator クラスも必要です。

メンバーへのアクセスは、アクセス権とモジュールの境界によって制限されます。外部入力の任意のクラス名やメソッド名を、そのままリフレクションの呼び出しに使わないでください。

## アノテーション：ツールへ情報を渡す :id=h-873bc94573d7

アノテーションはメタデータです。それ自体が業務処理を実行するのではなく、コンパイラー、ツール、フレームワークが読み取って処理します。

- @Override：スーパークラスやインターフェースのメソッドをオーバーライドしているか、コンパイラーが確認します。
- @Test：テストフレームワークがテストメソッドを識別します。
- @Controller：Spring がコントローラーを識別します。

独自のアノテーションでは、@Target が使える場所、@Retention が保持する段階を決めます。実行時にリフレクションで読むには、RetentionPolicy.RUNTIME が必要です。

参考：[JUnit 4 API](https://junit.org/junit4/javadoc/latest/)、[JUnit のドキュメント](https://docs.junit.org/)、[リフレクションのチュートリアル](https://docs.oracle.com/javase/tutorial/reflect/)。
