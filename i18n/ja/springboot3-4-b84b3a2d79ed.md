# Spring Boot 3から4への移行リファレンス :id=h-03638183f3f3

学習目標：更新前後で元のプロジェクトの観察可能な動作を維持し、依存関係、JSON、テスト、実行環境の変化を把握します。

**適用範囲：**&#x73FE;在の3.5.xの保守版から、対象の4.x安定版へ段階的に移行します。本文は移行順序を示すもので、リポジトリ内の古いチュートリアルがすべて自動移行済みとはしていません。

## 更新前に証拠を用意する :id=h-d866e508232e

JDK、Maven、Boot、DB、コンテナー、追加starterのバージョンを記録します。既存のAPI例、エラー応答、認証フロー、重要なテスト結果を保存します。

先に選択した3.5.xの保守版へ更新して非推奨事項に対応し、独立したブランチで4.xへ更新します。同時にDBモデルの書き換え、認証やJDKの変更、サービス分割を行って、回帰の原因を分からなくしないでください。

<a id="section-2"></a>

## 最小限の移行比較 :id=h-f15aa023be57

古い[SpringBoot.md](SpringBoot.md)はBoot 2.5の歴史的なチュートリアルであり、途中の変更を飛ばして直接適用できません。新しい[バックエンドのPOM](examples/taskboard/backend/pom.xml)は、独立したBoot 4.1.2の完全なサンプルです。

| 確認項目          | 必要な対応                                      |
| ------------- | ------------------------------------------ |
| Java          | Boot 4は最低Java 17が必要。対象のJDKについて第三者ライブラリも確認  |
| Servletコンテナー  | 対象Bootの要件にServlet 6.1とコンテナーのバージョンを合わせる     |
| モジュールとstarter | Boot 4はモジュールが細分化されているため、機能に対応するstarterを確認  |
| JSON          | Jackson 3の依存関係、インポート、独自設定の互換性を確認           |
| テスト           | テストモジュール、注釈のパッケージ、テストエンジンを確認               |
| 追加のエコシステム     | MyBatis、JoinFaces、Spring Cloudなどの互換性表を個別確認 |

このプロジェクトはspring-boot-starter-webmvcと対応するwebmvc-testを使います。サンプルの新しいテスト注釈のパッケージ名を、Boot 3プロジェクトへ機械的に適用しないでください。

## 実際の実行順序 :id=h-33f2911fff33

```powershell
mvn -B -ntp verify
mvn dependency:tree
```

更新前後の結果をそれぞれ保存します。まず依存関係の競合とコンパイルエラーを解決し、続いて起動と動作の差に対応します。

1. 対象バージョンを決め、parentまたはBOMを更新します。
2. starter、明示的な依存関係、プラグインを調整し、異なるメジャーバージョンの混在を避けます。
3. 非推奨APIの削除、パッケージパス、設定プロパティの変更を修正します。
4. データソース、移行、認証、JSON、例外応答を確認します。
5. 単体、結合、ブラウザーのテストを実行します。
6. 本番と同じコンテナーイメージとDBで練習します。
7. 移行後の構造で旧成果物にロールバックして実行できるか検証します。

<a id="section-4"></a>

## 重点的な回帰確認事項 :id=h-5f7087d2607a

日時、列挙型、空フィールド、未知のJSONフィールド、大きな整数、ページング形式、エラーステータス、Content-Typeを実際のリクエストで検証します。

フィルター順序、CSRF、ログインリダイレクト、Cookie属性、リソースパス、プロキシ転送も確認します。起動ログにエラーがなくても、元のプロジェクトと同じ動作とは限りません。

フレームワークが管理する依存関係は通常BOMで組み合わせます。1つのコンパイルエラーを消すために、Jackson、Security、Springの個別バージョンを勝手に上書きしないでください。

<a id="section-5"></a>

## よくあるエラーと早見表 :id=h-21918950df86

| 現象                             | 考えられる原因                 |
| ------------------------------ | ----------------------- |
| コンパイルは通るが実行時にNoSuchMethodError | 実行時の依存関係の組み合わせに互換性がない   |
| テスト注釈が見つからない                   | テストstarterまたはパッケージパスの変更 |
| JSON出力の変化                      | シリアライズのバージョン、モジュール、設定の差 |
| コンテナーへのデプロイ失敗                  | Servletとコンテナーのバージョン不一致  |
| ローカルでしか成功しない                   | CI JDK、イメージ、設定がローカルと異なる |

移行記録には検証方法とロールバック条件を含めます。旧バージョンのドキュメントには明確な表示を残し、新しい文書は独立したバージョンの手順にします。異なるバージョンの抜粋を同じプロジェクトに混ぜないでください。
