## 最小限の実行可能なサンプル :id=h-7dd27c75225c

ModernJavaDemo.javaとして保存します。

```java
import java.util.List;
import java.util.Objects;

public class ModernJavaDemo {
    record Task(long id, String title) {
        Task {
            Objects.requireNonNull(title, "title");
            title = title.strip();
            if (title.isEmpty()) throw new IllegalArgumentException("title is blank");
        }
    }

    public static void main(String[] args) {
        var tasks = List.of(new Task(1, " Learn Java "), new Task(2, "Write tests"));
        var titles = tasks.stream().map(Task::title).toList();
        System.out.println(titles);
    }
}
```

```powershell
javac -encoding UTF-8 --release 17 ModernJavaDemo.java
java ModernJavaDemo
```

想定出力は\[Learn Java, Write tests]です。List.ofとStream.toListが返すリストでは要素の追加や削除はできませんが、要素内部のすべてのオブジェクトまで不変にするわけではありません。

## record、Optional、時刻 :id=h-00965d60fe9f

recordはアクセサー、equals、hashCode、toStringを自動生成します。アクセサーはtitle()であり、getTitle()ではありません。フィールド参照が再代入不可でも、参照先のListが自動的に不変になるわけではありません。コレクションのコピーでも要素の可変性を考慮します。

Optionalは存在しない可能性のある戻り値に適し、通常はエンティティのフィールドやリクエストJSONには使いません。先にget()して例外で通常の分岐を代用しないでください。

業務上の日付にはLocalDate、絶対的な時点にはInstant、地域のタイムゾーン規則が必要ならZoneId / ZonedDateTimeを使います。DB、API、表示層のタイムゾーンを明確にしてください。LocalDateTime自体にタイムゾーンはありません。

金額にはBigDecimalを使い、小数桁数と丸め規則を明確にします。正確な金額をdoubleから構築せず、equalsと数値比較compareToを混同しないでください。

## 仮想スレッド：待機のコストを下げる :id=h-eb64fb76e7f3

以下はメソッド本体の抜粋です。クラスのメソッド内に配置し、JDK 21以降を使用してください。

```java
try (var executor = java.util.concurrent.Executors.newVirtualThreadPerTaskExecutor()) {
    var future = executor.submit(() -> "completed");
    System.out.println(future.get(2, java.util.concurrent.TimeUnit.SECONDS));
}
```

仮想スレッドはブロックして待機する大量のタスクに適し、CPU集約的な計算が自動的に速くなるわけではありません。スレッドが安価でも、DB接続、外部API、メモリは無限ではありません。

getのタイムアウトはタスクを自動キャンセルしません。業務に応じてcancelを呼び、タスクが割り込みに正しく応答するようにします。InterruptedExceptionを握りつぶさず、続行できない場合は割り込み状態を保持するか、メソッドの取り決めに従って上位へ伝えます。

## 検証とよくあるエラー :id=h-a8b0965689e1

コンパイルと実行のバージョンはjava -version、javac -version、mvn -versionで別々に確認します。IDEが動いてもCIが同じJDKを使うとは限りません。

DB呼び出しを並列Streamに包むだけでスループットが向上すると思わないでください。先に接続プール、外部のレート制限、遅延を測定します。共有するHashMap、カウンター、シングルトンBeanの可変フィールドにはスレッド安全性の配慮が必要です。

## 開発の早見表 :id=h-8efae9d8a41f

- 入口で引数の妥当性を検証し、業務の中核も自身の不変条件を守ります。
- 所有するリソースはtry-with-resourcesで閉じ、借りた接続は勝手に閉じたりコミットしたりしません。
- コレクションはアクセス方法に応じて選び、メソッド名だけで性能を判断しません。
- コンストラクター注入を優先し、制御しにくいグローバルな可変状態を減らします。
- JDKの更新時はビルドプラグイン、プロキシライブラリ、監視ツール、コンテナーのベースイメージも合わせて検証します。
