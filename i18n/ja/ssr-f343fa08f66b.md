# SSRとハイドレーションの原理 :id=h-a20a476ee778

## 4つの概念を混同しない :id=h-50e889bc9a3a

| 概念                 | 初期コンテンツの生成方法                           | 実行条件                    |
| ------------------ | -------------------------------------- | ----------------------- |
| CSR                | 業務画面は主にブラウザーでJavaScriptを実行した後に生成される    | 静的リソースの配信とデータAPI        |
| SSR                | サーバーがリクエスト処理時に初期HTMLを生成する。キャッシュとの併用も可能 | 対応するサーバー実行環境            |
| SSG / プリレンダリング     | ビルド時に既知のページのHTMLを生成する                  | 生成された静的コンテンツをデプロイする     |
| ハイドレーション Hydration | ブラウザーが一致するデータとコンポーネントでサーバーのHTMLを引き継ぐ   | クライアントスクリプトと一致する初期結果が必要 |

SPAはナビゲーションとアプリの構成方法を、SSRはHTMLの生成方法を表し、両者は完全な排他関係ではありません。SSRフレームワークはその後の移動にクライアントルーティングを使用でき、同一サイトでもページごとに方式を組み合わせられます。

React Server Componentsはサーバーコンポーネントとそのプロトコルの境界を表し、SSRと同義ではありません。サーバーコンポーネントはビルド時にもリクエスト時にもレンダリングに参加できます。クライアントコンポーネントも初回HTMLのプリレンダリングに参加する場合があります。

<a id="section-2"></a>

## 2つの実行可能なプロジェクトで観察する :id=h-ac1da6722a17

Nextのサンプルはexamples/next-ssr、Nuxtのサンプルはexamples/nuxt-ssrにあります。完全なコマンドと検証方法は[SSRサンプルの説明](examples/ssr/README.md)を参照してください。

まず1つのプロジェクトをビルドして起動し、curl.exeでホームページの生の応答を取得します。正常なら記事のリンクと見出しがすでに含まれており、ブラウザーのJavaScriptを無効にしても表示されます。

JavaScriptを有効にしたらdata-hydrated=trueを待ち、カウンターをクリックすると数字が0から1になります。サーバーがHTMLを返すことと、ページを操作できることは、それぞれ別に検証する結果です。

<a id="section-3"></a>

## ハイドレーションに必要な「一致」とは :id=h-eeb4521a6d44

サーバーとブラウザーの初回レンダリングは、互換性のある構造、テキスト、属性を生成する必要があります。両側の初回レンダリングでそれぞれ乱数や現在時刻を直接取得したり、異なるタイムゾーンに依存した書式設定を行ったりしないでください。

Nextはサーバーで計算した時刻をサーバー生成のコンテンツとして渡し、操作可能なカウンターの初期値は0に固定します。NuxtはuseStateでサーバーの初期値を保持し、payloadを通じてクライアントでも同じ値を使用します。

window、document、localStorageは対応するブラウザー環境にのみ存在します。読み取りはクライアントのマウント段階か、明示したクライアントコンポーネントの境界内で行い、モジュールのインポート時にはアクセスしないでください。

## 不一致のよくある原因 :id=h-29ba6474f1f5

| 原因       | 例                          | 修正の方針                        |
| -------- | -------------------------- | ---------------------------- |
| データの相違   | 両側が別々に取得して結果が異なる           | フレームワークのデータ受け渡しと初期payloadを使う |
| 時刻とロケール  | サーバーのUTCとブラウザーのローカルタイムゾーン  | 初期出力を統一し、マウント後にローカル形式を表示する   |
| 不正なHTML  | 許可されないタグの入れ子をブラウザーが組み替える   | 構造を修正する                      |
| ブラウザーの状態 | 初回レンダリングでlocalStorageを直接読む | 確定的な初期画面を用意し、マウント後に読み取る      |
| 外部からの変更  | 拡張機能や第三者のスクリプトがDOMを変更する    | 最小環境で再現し、変更元を特定する            |

suppressHydrationWarning、ClientOnly、SSRの無効化を、すべての問題の標準的な解決策にしないでください。本当にブラウザーでしか生成できない内容に限って、適切なプレースホルダーと読み込み動作を設計します。

## パフォーマンス、SEO、ストリーミング :id=h-fb1bef754f5b

SSRはコンテンツを早く表示できる場合がありますが、サーバー処理や上流データを待つコストも増えます。ハイドレーションには引き続きスクリプトのダウンロード、解析、実行が必要です。SSRがすべての指標を改善するとは限りません。

SSGとキャッシュは変更が少ない公開コンテンツに適しています。ユーザーの非公開コンテンツはまず分離を確保します。ストリーミングレンダリングは内容を分割して送信できますが、プロキシのバッファリング、エラーステータス、監視も合わせて対応する必要があります。

HTMLがあってもSEOが自動的に完成するわけではありません。タイトル、メタ情報、アクセス可能なリンク、正しいステータス、正規のURL、適切なサイトのコンテンツ戦略も必要です。

## 検証と開発の早見表 :id=h-fb72a47e7175

1. 本番ビルドを起動して確認し、devだけで済ませないでください。
2. スクリプト実行後のElementsパネルだけでなく、生のHTMLを確認します。
3. ブラウザーのJavaScriptを無効にし、想定した内容が残ることを確認します。
4. スクリプトを有効にし、ハイドレーションのログと操作を確認します。
5. 独立したブラウザーセッションで、ユーザーの状態が混ざらないことを確認します。
6. 存在しないページと上流障害のステータスを確認します。

[本番モードのテスト](examples/ssr/tests/rendering.spec.ts)では、両フレームワークのスクリプトなしの内容、ハイドレーションの操作、独立したブラウザー状態、未知の記事を確認します。実際のCDNや認証システム、すべてのコンポーネントがテスト済みであることは証明しません。
