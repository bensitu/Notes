## 1. TypeScript :id=h-ea28e1adacb7

### 1）動的型付けの問題 :id=h-80cf9d0a4a4d

前述のように JavaScript は動的型付けの言語です。例えば、次のとおりです。

```js
function test(obj) {
}
```

obj は単なる文字列かもしれない

```js
test('hello, world')
```

obj は関数かもしれない

```js
test(()=>console.log('hello, world'))
```

obj の型が不確かなため、後で使う人が困ります。引数を間違えるとコードが動かなくなります。

動的型付けとは：

- コードを実行して初めて何が起こるか分かる（running the code to see what happens）

静的型付けとは：

- コードが動く前に、期待される動作を予測する（make predictions about expected behavior before code runs）

次の TypeScript コードは、実行前に引数へ制約を加えます。

```typescript
function test(msg : string) {
}
```

- 引数に対して文字列の操作だけを許可する

```typescript
function test(msg : Function) {
  msg()
}
```

- 引数に対して関数の操作だけを許可する

### 2）入門 :id=h-36077e2fdd05

TypeScript コンパイラーをインストールする

```cmd
npm install -g typescript
```

TypeScript のコードを書く

```typescript
function hello(msg: string) {
  console.log(msg)
}

hello('hello,world')
```

tsc コマンドでコンパイルする

```cmd
tsc xxx.ts
```

コンパイルで JavaScript を生成し、型の情報は消去されます。

```js
function hello(msg) {
    console.log(msg);
}
hello('hello,world');
```

別の例として、interface でユーザーの型を定義します。

```ts
interface User {
  name: string,
  age: number
}

function test(u: User): void {
  console.log(u.name)
  console.log(u.age)
}

test({ name: 'zhangs', age: 18 })
```

コンパイル後

```js
function test(u) {
    console.log(u.name);
    console.log(u.age);
}
test({ name: 'zhangs', age: 18 });
```

このように、TypeScript はコンパイル時に型チェックする静的型付けの技術です。

#### ジェネリクス :id=h-85543cabb2bd

次の型宣言には明らかな共通点があります。

```typescript
interface RefString {
  value: string
}

interface RefNumber {
  value: number
}

interface RefBoolean {
  value: boolean
}

const r1: RefString = { value: 'hello' }
const r2: RefNumber = { value: 123 }
const r3: RefBoolean = { value: true }
```

次のように改善できます。

```typescript
interface Ref<T> {
  value: T
}

const r1: Ref<string> = { value: 'hello' }
const r2: Ref<number> = { value: 123 }
const r3: Ref<boolean> = { value: true }
```

- ジェネリクスの要点は `<类型参数>` です。型も変化する要素として引数のように渡し、似た構造の新しい型を作れます。

関数定義もジェネリクスに対応します。

```typescript
function ref<T>(n: T): Ref<T> {
  return { value: n }
}

const v1 = ref("hello"); 	// Ref<string>
const v2 = ref(123.3333);	// Ref<number>

v1.value.toLocaleLowerCase()
v2.value.toFixed(2)
```

### 5）クラス :id=h-ee06d3697ad4

> TypeScript と JavaScript のクラス構文は重点ではありません。class は補助的な役割で、ここでは先に説明した interface の方が重要です。

#### 基本構文 :id=h-552d1df06281

```typescript
class User {
    name: string;

    constructor(name: string) {
        this.name = name
    }
}

const u = new User('张三')
```

以下は古いターゲットでのコンパイル結果で、プロトタイプの理解用です。実際の出力は tsconfig.json の target によります。現在のプロジェクトでは、廃止された es3 ターゲットを使わないでください。

```js
var User = /** @class */ (function () {
    function User(name) {
        this.name = name;
    }
    return User;
}());
var u = new User('张三');
```

したがって JavaScript の class は Java の class と同じではなく、プロトタイプを基に実現されます。原理は第 2 章（036、037）を参照してください。

#### 継承とインターフェース :id=h-9d978b23ffbc

```typescript
interface Flyable {
  fly(): void
}

class Animal {
  name: string;
  constructor(name: string) {
    this.name = name
  }
}

class Bird extends Animal implements Flyable {
  fly() {
```

### 2）Vue コンポーネント :id=h-76cb835ae962

Vue のコンポーネントファイルは .vue で終わり、3 つの部分から成ります。

```vue
<script setup lang="ts"></script>

<template></template>

<style scoped></style>
```

- script：テンプレートのデータ元と動作を制御するコード部分
- template：HTML コードを生成するテンプレート部分
- style：スタイル部分。ここでは通常あまり扱いません。

ルートコンポーネントは src/App.vue です。まず Hello, World の例を書きます。

```vue
<script setup lang="ts">
import { ref } from "vue";
let msg = ref("hello"); // See note 1 below.

function change() {
  msg.value = "world";
  console.log(msg);
}
</script>
<template>
  <h1>{{ msg }}</h1>
  <input type="button" value="修改msg" @click="change" />
</template>
```

例の説明：

1. データをリアクティブにする

- {{msg}} は変数をページの特定の位置にバインドします。
- 通常の変数もテンプレートに表示できます。値の変更でページを自動更新するには、ref、reactive、computed などのリアクティブな API を使います。
  - ref はリアクティブなデータを返し、データが変わるとページの表示も変わります。

#### main.ts :id=h-2175d5e1cf54

```typescript
import { createApp } from 'vue'
import './style.css'
import App from './App.vue'

createApp(App)
  .mount('#app')
```

- createApp は Vue アプリケーションを作成します。引数の App は、先に見たルートコンポーネントです。
- mount は、ルートコンポーネントが生成した HTML 断片を、index.html 内の id が app の要素にマウントします。

自分のコンポーネントファイルを変更し、メインページにマウントできます。

src/views/E0.vue を作成し、次の内容を記述します。

```vue
</template>
```

#### ref と reactive :id=h-9eb73c7ed9cf

Vue はデータをリアクティブにする関数を 2 つ提供します。

```vue
<script setup lang="ts">
import { ref, reactive } from 'vue'
const msg = ref('Hello, World')
const user = reactive({ name: '张三' })
</script>

<template>
  <h2>{{msg}}</h2>
  <h2>{{user.name}}</h2>
</template>
```

- ref は任意の型のデータをリアクティブにできます。
- reactive はオブジェクト型だけをリアクティブにでき、string、number、boolean などの基本型には使えません。

もう 1 つの違い：

```vue
<script setup lang="ts">
import { ref, reactive } from 'vue'
const u1 = ref({ name: '张三' })
const u2 = reactive({ name: '张三' })

function test() {
  console.log(u1.value)
  console.log(u2)
}

test()
</script>

<template>
  <h2>{{u1.name}}</h2>
  <h2>{{u2.name}}</h2>
</template>
```

- template で ref のデータを使う場合、変数名だけでアクセスできます。
- コード内で ref のデータを使う場合は、変数名.value が必要です。
- reactive のデータは、テンプレートとコードで同じように使えます。

#### xhr :id=h-2eb1136dd24e

ブラウザーには、バックエンドとリクエストを送受信する API が 2 つあります。Fetch API は前述のとおりで、もう 1 つの XHR の基本的な使い方は次のとおりです。

```js
const xhr = new XMLHttpRequest()
xhr.onload = function() {
    console.log(xhr.response)
}
xhr.open('GET', 'http://localhost:8080/api/students')
xhr.responseType = "json"
xhr.send()
```

この API は高機能ですが古く、Promise に直接対応しないため、ラップする必要があります。

```typescript
function get<T>(url: string): Promise<T> {
  return new Promise<T>((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open("GET", url);
    xhr.responseType = "json";
    xhr.timeout = 5000;
    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(xhr.response as T);
      } else {
        reject(new Error("HTTP " + xhr.status));
      }
    };
    xhr.onerror = () => reject(new Error("Network error"));
    xhr.ontimeout = () => reject(new Error("Request timed out"));
    xhr.onabort = () => reject(new Error("Request was cancelled"));
    xhr.send();
  });
}
```

このラッパーは成功、HTTP エラー、ネットワークエラー、タイムアウト、キャンセルを処理します。T はコンパイル時の型情報だけで、サーバーの JSON 構造を実行時に検証しません。厳密な検証が必要ならレスポンスの内容を別途確認します。

- Promise は非同期操作のラッピングに適し、await と組み合わせられます。
- Promise コンストラクターは通常の関数またはアロー関数の executor を受け取ります。引数の resolve、reject で結果を決めます。
  - 非同期操作が成功したら resolve に結果を渡し、その結果が await の値になります。
  - 非同期操作が失敗したら reject に失敗の結果を渡し、最終的に catch で捕捉します。
- await は Promise 内で resolve または reject が呼ばれるまで待ってから、後続処理に進みます。

呼び出し例 1：プロキシを使わず await で結果を受け取る

```js
try {
  const resp = await get("http://localhost:8080/api/students")
  console.log(resp)
} catch (e) {
  console.error(e)
}
```

呼び出し例 2：プロキシを経由する

```js
try {
  const resp = await get('/api/students')
  console.log(resp)
} catch(e) {
  console.log(e)
}
```

- プロキシは転送処理を 1 回追加します。実際の所要時間はネットワークと実装によるため、1 つの例だけで常に明らかに遅いとは判断できません。

### 4）JSX コンポーネント :id=h-0832c4b700d8

まずインストールします。

```cmd
@vitejs/plugin-vue-jsx
```

vite.config.ts を設定する

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'

// https://vitejs.dev/config/
export default defineConfig({
  plugins: [vue(), vueJsx()]
})
```

Hello.tsx コンポーネントを作成する

```tsx
import { defineComponent, ref } from 'vue';
export default defineComponent(() => {
  const msg = ref("你好!");
  return () => <h2>{msg.value}</h2>;
});
```

その後、ほかのコンポーネントから使います。

```vue
<script setup lang="ts">
import Hello from './views/Hello'
</script>

<template>
  <Hello></Hello>
</template>
```

JSX なら template では実現しにくい機能も実装できます。
