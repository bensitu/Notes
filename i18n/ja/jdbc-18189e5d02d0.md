# JDBC の基礎とトランザクション :id=h-068dd90a9e7d

Java から SQL を実行し、接続、検索結果、バッチ書き込み、トランザクションを適切に扱います。

## JDBC とは :id=h-7fbfee9f1f5b

JDBC は、Java からリレーショナルデータベースにアクセスするための標準 API で、主に java.sql と javax.sql パッケージにあります。データベースの提供元が JDBC ドライバーを用意し、Java のコードが標準インターフェース経由で呼び出します。MyBatis や JdbcTemplate などは JDBC を土台に、繰り返し必要になる処理をまとめています。

永続化とは、再起動後も読み出せる保存先にデータを保存することです。データベースやファイルがその例で、リレーショナルデータベースだけに限りません。

<a id="section-2"></a>

## 実行環境と練習用テーブル :id=h-8b5a5f36d1cb

例では Java 8 以降、MySQL 8.x、Connector/J 8.x、InnoDB を使います。ドライバーとデータベースのバージョンは別のものです。com.mysql.cj.jdbc.Driver はドライバーのクラス名で、データベースが 5.7 か 8.0 かだけでドライバーのパッケージ名を決めないでください。

最初に練習用データベースにテーブルを作成します。実行時は自分のデータベースアカウントを使い、実際のパスワードをリポジトリにコミットしないでください。

```sql
CREATE TABLE account (
    id BIGINT NOT NULL,
    balance DECIMAL(12, 2) NOT NULL,
    PRIMARY KEY (id)
) ENGINE=InnoDB;
INSERT INTO account (id, balance) VALUES (1, 100.00), (2, 20.00);

CREATE TABLE batch_item (
    id BIGINT NOT NULL AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Maven にドライバーの依存関係を追加します。以下の固定バージョンは、この例を再現するためのものです。

```xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>8.4.0</version>
    <scope>runtime</scope>
</dependency>
```

JDBC 4 のドライバーは、実行時の classpath にドライバーの JAR があれば、通常は自動登録されます。Class.forName は古いドライバーへの対応や読み込みの調査に使えますが、接続のたびに必須となるものではありません。

## URL と接続設定 :id=h-481c541f140c

JDBC URL の基本形は jdbc:サブプロトコル:サブ名です。MySQL の例を示します。

```properties
url=jdbc:mysql://localhost:3306/study?characterEncoding=UTF-8
user=study_user
password=replace-with-your-local-password
```

ファイル名を jdbc.properties とし、src/main/resources に置きます。study データベースと接続アカウントは、あらかじめ用意してください。

タイムゾーンの指定は、実際の日時処理の要件に合わせてください。エラーを消すためだけに一律で UTC にしてはいけません。SSL エラーでは証明書とサーバー・クライアントの設定を確認し、安易に useSSL=false で暗号化を無効にしないでください。

ファイル：JDBCUtils.java。

```java
import java.io.IOException;
import java.io.InputStream;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.util.Properties;

public final class JDBCUtils {
    private JDBCUtils() {}

    public static Connection getConnection() throws IOException, SQLException {
        Properties properties = new Properties();
        try (InputStream input = JDBCUtils.class.getResourceAsStream("/jdbc.properties")) {
            if (input == null) {
                throw new IOException("jdbc.properties was not found on the classpath");
            }
            properties.load(input);
        }
        return DriverManager.getConnection(
            properties.getProperty("url"),
            properties.getProperty("user"),
            properties.getProperty("password"));
    }
}
```

このクラスは、設定の読み込みと接続の取得だけを示すものです。実際の運用では通常、フレームワークの設定と接続プールを使い、クエリのたびに設定ファイルを読み直さないようにします。

## PreparedStatement による追加・更新・削除 :id=h-87d6af03265c

Connection.prepareStatement(sql) を使います。メソッド名は prepareStatement です。

? は、後から値を設定するパラメーターを表し、番号は 1 から始まります。設定したデータ値は SQL の構造として解釈されないため、文字列連結より安全です。ただし、テーブル名、列名、並べ替え方向などの SQL の構造は ? で設定できず、プログラム側で制御する必要があります。

ファイル：JdbcOperations.java。後のトランザクションの例でも、このメソッドを使います。

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public final class JdbcOperations {
    private JdbcOperations() {}

    public static int update(Connection connection, String sql, Object... values)
            throws SQLException {
        try (PreparedStatement statement = connection.prepareStatement(sql)) {
            for (int i = 0; i < values.length; i++) {
                statement.setObject(i + 1, values[i]);
            }
            return statement.executeUpdate();
        }
    }
}
```

executeUpdate が返すのは変更された行数で、自動生成された主キーではありません。次はメソッド内に置く断片です。BigDecimal と Connection をインポートしてください。

```java
try (Connection connection = JDBCUtils.getConnection()) {
    int rows = JdbcOperations.update(connection,
        "UPDATE account SET balance = ? WHERE id = ?",
        new BigDecimal("120.00"), 1L);
    System.out.println(rows);
}
```

| メソッド               | 主な用途                    | 戻り値                                   |
| ------------------ | ----------------------- | ------------------------------------- |
| executeQuery()     | SELECT による検索            | ResultSet                             |
| executeUpdate()    | INSERT・UPDATE・DELETE など | 変更された行数。一部のほかの文では 0                   |
| execute()          | 結果の型が不明な場合や、結果が複数ある場合   | 最初の結果が ResultSet かどうか。操作が成功したかどうかではない |
| getGeneratedKeys() | 自動生成されたキーの取得            | ドライバーが対応していれば、自動生成されたキーの結果セットを返す      |

## ResultSet と検索結果のマッピング :id=h-355abe3f8515

ResultSet のカーソルは、最初の行より前にあります。next() は次の行へ移動し、その行が存在すれば true を返します。

```java
try (Connection connection = JDBCUtils.getConnection();
     PreparedStatement statement = connection.prepareStatement(
         "SELECT id, balance AS available_balance FROM account WHERE id = ?")) {
    statement.setLong(1, 1L);
    try (ResultSet result = statement.executeQuery()) {
        if (result.next()) {
            long id = result.getLong("id");
            BigDecimal balance = result.getBigDecimal("available_balance");
            System.out.println(id + ": " + balance);
        }
    }
}
```

この断片はメソッド内に置きます。java.sql.Connection、PreparedStatement、ResultSet、java.math.BigDecimal をインポートし、IOException と SQLException を処理するか、throws で宣言してください。

| Java の型                      | 一般的な JDBC / SQL の対応                                             |
| ---------------------------- | --------------------------------------------------------------- |
| int / Integer                | INTEGER                                                         |
| long / Long                  | BIGINT                                                          |
| BigDecimal                   | DECIMAL / NUMERIC                                               |
| String                       | CHAR / VARCHAR / テキスト                                           |
| byte\[]                      | バイナリ列                                                           |
| java.sql.Date                | DATE                                                            |
| java.sql.Time                | TIME                                                            |
| java.sql.Timestamp           | TIMESTAMP                                                       |
| LocalDate / LocalDateTime など | JDBC 4.2 では、getObject / setObject によって、ドライバーが対応する日付型との間で変換できます。 |

SQL の NULL と Java の数値 0 は別のものです。getInt や getLong などは NULL を読むと 0 を返すことがあるため、wasNull() で確認します。適切な getObject のオーバーロードを使い、ラッパー型で受け取る方法もあります。

ResultSetMetaData は列の情報を表します。getColumnCount は列数、getColumnLabel は別名または列ラベル、getColumnName は元の列名を返します。

リフレクションでオブジェクトのフィールドへ自動設定する場合も、別名、継承したプロパティ、null、型変換への対応が必要です。getDeclaredField と field.set だけで、すべての検索に使える汎用 Mapper になるわけではありません。最初は各列の対応を明示し、その後に成熟したフレームワークを使いましょう。

## リソースの解放とエラー処理 :id=h-58201f82357d

try-with-resources はブロックを抜けるときにリソースを閉じ、例外が起きてもクローズを試みます。上の入れ子の例では、ResultSet、PreparedStatement、Connection の順に閉じます。

データベースの例外を表示するだけで null や 0 を返してはいけません。呼び出し元が「実行失敗」を「該当なし」や「変更なし」と誤解します。SQLException はトランザクションの境界か、明確に決めたエラー処理層へ伝えてください。

## バッチ書き込み :id=h-39fe37086f3f

PreparedStatement.addBatch() は現在のパラメーター値を記録し、executeBatch() が記録したバッチを実行します。通常の Statement の addBatch(String) は SQL の文字列を受け取るもので、混同しないでください。

Connector/J の rewriteBatchedStatements=true は、ドライバー側のバッチ最適化です。MySQL サーバーで「バッチ処理を有効にする」設定ではありません。URL に既存のパラメーターがあれば &、なければ ? で追加します。

ファイル：BatchExample.java。

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;

public class BatchExample {
    public static void main(String[] args) throws Exception {
        try (Connection connection = JDBCUtils.getConnection()) {
            connection.setAutoCommit(false);
            try (PreparedStatement statement = connection.prepareStatement(
                    "INSERT INTO batch_item (name) VALUES (?)")) {
                for (int i = 1; i <= 23; i++) {
                    statement.setString(1, "item-" + i);
                    statement.addBatch();
                    if (i % 10 == 0) {
                        statement.executeBatch();
                        statement.clearBatch();
                    }
                }
                statement.executeBatch();
                statement.clearBatch();
                connection.commit();
            } catch (SQLException | RuntimeException exception) {
                try {
                    connection.rollback();
                } catch (SQLException rollbackFailure) {
                    exception.addSuppressed(rollbackFailure);
                }
                throw exception;
            }
        }
    }
}
```

ここでは 10 件ごとに実行し、最後に残りの 3 件も実行して、1 バッチ未満のデータを取りこぼさないようにします。バッチの実行とトランザクションのコミットは別の操作です。上の例は複数のバッチを実行した後、まとめてコミットします。

## トランザクション：複数の操作をまとめて成功または失敗させる :id=h-fc8786baceed

新しい JDBC 接続は既定で自動コミットです。setAutoCommit(false) の後は、明示的に commit または rollback してください。close による自動コミットを当てにしてはいけません。進行中のトランザクションがあるときの close の動作は、ドライバーの実装によります。

同じローカルトランザクション内の SQL は、同じ Connection を使う必要があります。DAO は途中で別の接続を取得したり、呼び出し元から借りた接続を勝手に閉じたりしてはいけません。

次の送金例では、金額を BigDecimal で扱います。2 件の口座レコードは、前の SQL で用意します。

ファイル：TransferExample.java。

```java
import java.math.BigDecimal;
import java.sql.Connection;
import java.sql.SQLException;

public class TransferExample {
    public static void transfer(long fromId, long toId, BigDecimal amount)
            throws Exception {
        if (fromId == toId || amount == null || amount.signum() <= 0) {
            throw new IllegalArgumentException("Invalid transfer");
        }
        try (Connection connection = JDBCUtils.getConnection()) {
            connection.setAutoCommit(false);
            try {
                int debited = JdbcOperations.update(connection,
                    "UPDATE account SET balance = balance - ? " +
                    "WHERE id = ? AND balance >= ?",
                    amount, fromId, amount);
                if (debited != 1) {
                    throw new SQLException("Source account is missing or funds are insufficient");
                }
                int credited = JdbcOperations.update(connection,
                    "UPDATE account SET balance = balance + ? WHERE id = ?",
                    amount, toId);
                if (credited != 1) {
                    throw new SQLException("Destination account is missing");
                }
                connection.commit();
            } catch (SQLException | RuntimeException exception) {
                try {
                    connection.rollback();
                } catch (SQLException rollbackFailure) {
                    exception.addSuppressed(rollbackFailure);
                }
                throw exception;
            }
        }
    }

    public static void main(String[] args) throws Exception {
        transfer(1L, 2L, new BigDecimal("10.00"));
    }
}
```

引き落とし条件に残高確認を含め、残高が負になるのを防ぎます。入金に失敗すると例外を投げ、引き落としもロールバックします。逆方向の送金を同時実行するとデッドロックが起こることがあり、データベースは一方のトランザクションを失敗させます。再試行はトランザクション全体の外側で回数制限と冪等性を設計し、1 つの UPDATE 文だけを再試行しないでください。

この例は自分で接続を取得し、閉じます。外部の接続を借りるユーティリティーでは、呼び出し元がトランザクションと接続状態を管理します。接続プールを使う場合は、先にコミットかロールバックを終え、その後でプールの規約に従って状態を戻してください。setAutoCommit(true) 自体が未完了のトランザクションをコミットする場合があるため、ロールバックの代わりにはなりません。

## DAO の責務 :id=h-6385f9c5741c

DAO はデータベースへのアクセスをまとめるもので、業務ロジックを表すものではありません。まず明確なインターフェースを定義しましょう。

```java
public interface AccountDao {
    int debit(Connection connection, long id, BigDecimal amount) throws SQLException;
    int credit(Connection connection, long id, BigDecimal amount) throws SQLException;
}
```

これはインターフェースの断片です。該当する java.sql と java.math の型をインポートしてください。Service のトランザクション境界から接続を渡し、2 回の呼び出しで同じ接続を使います。

検索結果がなければ Optional や空のコレクションを返せますが、データベースへのアクセス失敗では例外を投げるべきです。同じ null で「データがない」と「実行に失敗した」の両方を表さないでください。

## DataSource と接続プール :id=h-bfc9bca6015b

DataSource は接続を取得するための標準インターフェースで、すべての実装が接続プールを持つわけではありません。接続プールは物理接続を再利用し、繰り返し接続を作るコストを減らします。

```java
try (Connection connection = dataSource.getConnection()) {
    // Execute database work with this connection.
}
```

dataSource はアプリケーションの起動時に設定します。プールから取得した接続の close は、通常、その接続をプールへ返します。アプリケーション終了時にはプール自体も閉じてください。リクエストのたびに新しいプールを作ってはいけません。

| 実装            | 保守時に確認すること                                                          |
| ------------- | ------------------------------------------------------------------- |
| HikariCP      | Spring Boot の JDBC starter で一般的な既定のプール。バージョンと設定は Boot に管理させる        |
| Druid         | プロジェクトの Boot のメジャーバージョンに合う starter を使い、ほかのバージョンの設定をそのままコピーしないでください。 |
| Apache DBCP 2 | パッケージ名は org.apache.commons.dbcp2 で、古い DBCP 1 とは異なる                  |
| C3P0          | 古いプロジェクトでよく使われる。実際のバージョンに対応する設定を確認する                                |

1 つのアプリケーションで複数の DataSource を使えます。例えば、2 つのデータベースへ接続する場合です。「通常は 1 つ」という構成を、「必ず 1 つでなければならない」という規則と取り違えないでください。

## Apache Commons DbUtils :id=h-d6e6f723b6e5

DbUtils は JDBC のパラメーター設定と結果処理をさらにまとめたものです。QueryRunner が SQL を実行し、ResultSetHandler が結果のマッピング方法を決めます。

| Handler                         | 結果                              |
| ------------------------------- | ------------------------------- |
| ArrayHandler / ArrayListHandler | 1 行を配列にする / 複数行を配列のリストにする       |
| BeanHandler / BeanListHandler   | 1 つの JavaBean / Bean のリスト       |
| MapHandler / MapListHandler     | 1 行を Map にする / 複数行を Map のリストにする |
| ColumnListHandler               | 特定の列の値のリスト                      |
| ScalarHandler                   | COUNT(\*) などの単一の値               |
| KeyedHandler                    | 指定列をキーにして、各行の Map をまとめる         |

トランザクション内では、Connection を受け取る QueryRunner のオーバーロードを使います。同じトランザクション内で、自分で接続を取得するオーバーロードへ切り替えてはいけません。Bean へのマッピングでは、列ラベルとプロパティー名が一致することも確認してください。

参考：[Connection API](https://docs.oracle.com/en/java/javase/17/docs/api/java.sql/java/sql/Connection.html)、[Connector/J のバッチ最適化](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-performance-extensions.html)、[DbUtils](https://commons.apache.org/proper/commons-dbutils/)。
