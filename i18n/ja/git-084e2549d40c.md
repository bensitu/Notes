# Gitとチーム開発：変更からマージまで :id=h-99db572e47dd

学習目標：ファイルの現在の状態を把握し、小さな変更をコミットし、競合を解決し、公開済みの誤りを安全に取り消せるようにします。

**適用範囲：**&#x47;it 2.xです。コマンドはPowerShellとBashの両方で使用できます。練習は自分のブランチで行ってください。

## まず4つの場所を理解する :id=h-feb6894e5658

作業ツリーはディスク上のファイル、ステージング領域は次のコミットに準備した内容、ローカルコミットは既存の履歴、リモートは共同作業用サーバー上のリポジトリです。保存しても自動的にステージされず、コミットしても自動的にpushされません。

| コマンド                 | 確認または変更するもの                |
| -------------------- | -------------------------- |
| git status           | 作業ツリー、ステージング領域、ブランチの状態を確認  |
| git diff             | 未ステージの変更を確認                |
| git diff --cached    | コミット予定の変更を確認               |
| git log --oneline -5 | 最近のコミットを確認                 |
| git fetch origin     | リモート追跡情報を更新し、作業ツリーは自動変更しない |

<a id="section-2"></a>

## 最小限の練習：説明を編集してコミットする :id=h-5cb4e82cd692

まずリポジトリのルートで実行します。未コミットの変更がある場合は、今回の作業に属するものを明確にし、そのまますべてをステージしないでください。

```powershell
git status
git fetch origin
git switch main
git pull --ff-only
git switch -c feature/update-taskboard-guide
```

このプロジェクトの説明を編集したら、対象ファイルのみをステージします。

```powershell
git diff -- examples/taskboard/README.md
git add -- examples/taskboard/README.md
git diff --cached --check
git diff --cached
git commit -m "docs: clarify taskboard startup"
git push -u origin feature/update-taskboard-guide
```

ここでのファイルは練習対象ですが、練習のために無意味な変更を作らないでください。コミットの理由は1文で説明できるようにします。push後はPull Requestで他のメンバーにレビューを依頼します。

<a id="section-3"></a>

## 競合の処理 :id=h-1f1db562390a

競合はGitが2つの変更の組み合わせを自動判断できないことを表し、どちらか一方を選べば必ず正しいという意味ではありません。

1. git statusで競合ファイルを特定します。
2. 両方の変更の意図を読み、最終的な内容に編集して競合マーカーを削除します。
3. 周辺の段落、リンク、サンプルの整合性を確認します。
4. 解決したファイルをステージし、mergeではコミット、rebaseではgit rebase --continueを実行します。
5. 現在の処理を続けられない場合は、操作に対応するgit merge --abortまたはgit rebase --abortを使用します。

共有ブランチのコミットを安易に書き換えないでください。チームの取り決めに従ったコミット整理に適するのは、自分の未公開ブランチです。公開済みブランチの更新が必要な場合は事前に調整し、--force-with-leaseの検証範囲を理解してください。

## 取り消し操作の早見表 :id=h-566ec5b93851

| 状況                     | 操作                                      | 注意事項                           |
| ---------------------- | --------------------------------------- | ------------------------------ |
| 誤ったファイルをステージした         | git restore --staged -- ファイル名           | ステージを解除し、作業ツリーの内容は保持する         |
| 直前のローカルコミットでファイルを入れ忘れた | 追加でステージしてgit commit --amend             | コミットIDが変わるため、共有履歴の安易な書き換えに使わない |
| 公開済みコミットで問題が発生した       | git revert コミットID                       | 逆の変更を行う新しいコミットを作り、確認とテストを行う    |
| 作業ツリーの変更を破棄したい         | 先にdiffを確認し、git restore -- ファイル名を実行するか判断 | そのファイルの未コミットの内容を上書きする          |

reset --hardや強制pushを万能な修復方法として扱わないでください。誤操作後は履歴の書き換えを止め、git reflogを確認します。未コミットかつ未バックアップのデータは復元できる保証がありません。

<a id="section-5"></a>

## 検証とよくあるエラー :id=h-0f0de8d28707

コミット前にステージ済みのdiffを確認し、コミット後にgit show --stat HEADを確認します。push後はfetchし、ローカルとリモートのブランチを比較します。「作業ツリーがクリーン」は「push済み」と同義ではありません。

マージ前に少なくとも変更に対応するテストとビルドを実行します。本文とサンプルは同期して変更し、パスワード、.env、データベースファイル、node_modules、ビルドディレクトリをコミットしないでください。

依存関係を追加したらロックファイルもコミットします。無視設定は新しいファイルの追跡を防ぐだけで、コミット済みの秘密情報を履歴から自動削除しません。漏えい時は認証情報を失効させ、チームの手順で履歴を処理します。
