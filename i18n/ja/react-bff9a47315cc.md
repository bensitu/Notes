## Reactの役割 :id=h-b9b02a68d5d4

Reactはデータに基づいて画面を記述し、更新をページに反映します。コンポーネントは画面の記述を返す関数であり、HTML文字列のテンプレートではありません。通常の関数呼び出し、レンダリング、DOM更新もそれぞれ異なる処理です。

JSXはJavaScriptの構文拡張で、TSXはその型チェックを提供します。変数は波括弧の中に記述し、コンポーネント名は大文字で始め、タグを閉じます。classNameはCSSのクラス、htmlForはlabelの関連付け属性に対応します。

## 最小限の実行手順 :id=h-4b840138caaf

リポジトリのルートで別のターミナルを開き、まず[タスク管理の説明](examples/taskboard/README.md)に従ってJavaバックエンドを起動します。ReactとVueは同じAPIを使用しますが、ページのプロジェクトは独立しています。

```powershell
Set-Location examples/react-taskboard
npm ci
npm run dev
```

[http://127.0.0.1:5174](http://127.0.0.1:5174)を開き、adminとバックエンドのAPP_PASSWORDでログインします。タスクを入力、送信、完了して画面を観察してください。ここではCSRのシングルページアプリを使用します。SSRは対応する別のドキュメントを参照し、両者を同じ実行方式として扱わないでください。

## 最初のコンポーネントと状態 :id=h-81ddc92e14ab

次のコンポーネントはTSXファイルに記述できます。ページでインポートして使用してください。

```tsx
import { useState } from 'react';

export function Counter({ initial = 0 }: { initial?: number }) {
  const [count, setCount] = useState(initial);
  return <button onClick={() => setCount(value => value + 1)}>
    点击次数：{count}
  </button>;
}
```

propsは親コンポーネントから渡され、子は直接変更しません。stateは、現在のコンポーネントが保持する必要があり、表示に影響するデータに使用します。setterの呼び出しは次のレンダリングを要求するもので、現在の関数実行中の変数を変更しません。

initialを渡しても、その後のpropsの変化でstateが自動的にリセットされるわけではありません。同期が必要な場合は、まずコンポーネントの同一性、制御された状態、リセット規則を明確にし、すべてのpropsをコピーするEffectを安易に追加しないでください。

## イベント、フォーム、コンポーネント間の通信 :id=h-0b56630deb58

onClick={handleClick}は関数を渡します。onClick={handleClick()}はレンダリング中に関数を呼び出します。イベントで追加の引数が必要な場合は、アロー関数で呼び出しを包むことができます。

制御された入力にはvalueとonChangeを使用します。フォームの送信にはonSubmitを使用し、必要に応じてpreventDefaultを呼び出します。パスワードはlocalStorageに保存せず、ログにも出力しません。ブラウザーのフィールド検証はフィードバックを改善しますが、サーバーでも独立した検証が必要です。

[TaskForm.tsx](examples/react-taskboard/src/TaskForm.tsx)は自身の入力を管理し、親から渡されたonAddを呼び出します。親は成功または失敗を返します。フォームは成功時のみ空にし、失敗時はユーザーが修正できるように文字を残します。

## リスト、更新、状態の管理場所 :id=h-662664d94b35

リストのkeyには安定した業務上のIDを使用します。挿入、並べ替え、絞り込みを行う場合、配列の添字を安定した識別子として使用しないでください。keyは通常のpropとして子に自動的に渡されません。

オブジェクトや配列を変更するときは新しい値を作成します。既存のstateに直接pushしても、Reactが検出するとは限りません。前の値が必要な場合は関数形式のsetterを使用します。新しい参照はディープコピーではなく、入れ子のオブジェクトも適切な境界で更新する必要があります。

共有データは共通の親に置き、入力欄だけに属するデータはフォームに残します。最初からすべての一時的な状態をグローバルライブラリに入れないでください。サンプルでは、同期がずれやすい件数を別途保持せず、残りのタスク数をタスクリストから直接計算します。

## 検証と開発の早見表 :id=h-eaa4d71a544a

```powershell
npm test
npm run build
```

| 症状                   | 確認事項                                              |
| -------------------- | ------------------------------------------------- |
| 入力を変更できない            | onChangeを指定しているか、undefinedと文字列を混用していないかを確認        |
| クリック前にリクエストが実行される    | JSX内でハンドラーを呼び出していないかを確認                           |
| リスト更新後に入力内容が別の行と混ざる  | keyが安定しているか、状態を誤ったコンポーネントに置いていないかを確認              |
| setState後も古い値が読み取られる | 現在のイベントのクロージャーには、このレンダリングの状態スナップショットが見える          |
| HTMLを含む内容が文字として表示される | 通常のテキストのエスケープです。このためにユーザー入力の危険なHTML出力を有効にしないでください |

Reactは完全なルーティング、リクエストキャッシュ、サーバーへのデプロイを自動的には提供しません。開発基盤やSSRの機能は、対応するツールやフレームワークが担います。
