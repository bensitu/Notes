# Pythonの開発基盤：環境、依存関係、チェック、テスト :id=h-a42424387beb

学習目標：別のマシンでも同じプロジェクトをインストール、検証、実行できるようにします。先に基本構文とコマンドラインを習得してください。

**適用範囲：**&#x4E00;貫したサンプルプロジェクトではPython 3.15、uv 0.13.7、pyproject.toml、uv.lock、Ruff、pytestを使用します。各パッケージのバージョンは固定されており、読者が最新の依存関係を手作業で組み合わせる必要はありません。

## 各プロジェクトファイルの役割 :id=h-c24bb1351a20

| ファイルまたはディレクトリ     | 用途                      | コミットするか |
| ----------------- | ----------------------- | ------- |
| pyproject.toml    | プロジェクトのメタデータ、依存関係、ツール設定 | はい      |
| uv.lock           | 解決済みの依存関係とハッシュ          | はい      |
| .python-version   | プロジェクトのインタープリターバージョンの選択 | はい      |
| .venv             | ローカルの仮想環境               | いいえ     |
| src/task_tools    | インストール可能なPythonパッケージ    | はい      |
| tests             | 動作のテスト                  | はい      |
| \*.db、キャッシュディレクトリ | ローカルの実行データやツールのキャッシュ    | いいえ     |

仮想環境はPythonパッケージを分離しますが、データベース、OSのツール、サービスポートは自動的に分離しません。.venvをすべてのマシンにコピーして実行できる成果物として扱わないでください。

## 最小限の実行手順 :id=h-d2f7f7483c50

まずuvの公式インストール手順に従って、自分のマシンに適したuvをインストールします。その後、次を実行します。

```powershell
Set-Location examples/taskboard/python
uv --version
uv sync --locked --all-extras
uv run --locked python --version
uv run --locked task-tools sample.csv
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest
```

初回はプロジェクトが要求するインタープリターと依存関係をダウンロードします。想定されるCSV集計はtotal=2、completed=1、pending=1です。インタープリターのダウンロードにはネットワークが必要です。ローカルのpythonが別のバージョンだからといって、ロックファイルを削除しないでください。

## 依存関係の追加と更新 :id=h-462153bb9a1a

```powershell
uv add package-name
uv add --dev development-tool-name
```

これはコマンド構文のテンプレートです。まず仮の名前を確認済みの実際のパッケージ名に置き換えます。実行後にpyproject.tomlとuv.lockを確認し、チェック、テスト、実際の実行を行います。

CIは--lockedを使用し、不整合があれば失敗します。パイプライン内で一時的にロックを修正しないでください。意図的に更新する場合は、開発ブランチで依存関係を更新して変更内容を読み、2つのファイルをコミットします。

[このプロジェクトの設定](examples/taskboard/python/pyproject.toml)では、キャッシュ、メッセージング、MongoDBのクライアントをservices extraにまとめています。テストにはメッセージの重複排除が含まれるため、共通の実行手順では--all-extrasを使用します。範囲を絞ってインストールする場合は、使用できないモジュールとテストを明確にします。

## パッケージ、モジュール、コマンドラインのエントリーポイント :id=h-897a4ba327f2

python -m task_tools.cliはモジュールとして実行します。task-toolsはインストール後にproject.scriptsが生成するエントリーポイントです。任意のディレクトリから内部ファイルを直接実行すると、パッケージのインポートパスが壊れる場合があります。

srcレイアウトにより、現在のディレクトリから偶然同名ファイルをインポートするのではなく、インストール済みパッケージに近い動作でテストできます。自分のファイルにjson.pyやtyping.pyなど、標準ライブラリを隠してしまいやすい名前を付けないでください。

## テスト、書式設定、型チェック :id=h-67068220e9f8

Ruffは明らかな誤りと選択した規則を検査し、formatは書式を統一し、pytestは動作のアサーションを実行します。業務上の正しさを証明するものではなく、互いの代わりにもなりません。

型注釈は実行時にデータを自動検証しません。完全な静的型チェックが必要な場合は、互換性のあるチェッカーを別途選択して固定し、第三者ライブラリの型と境界を段階的に補います。このサンプルはRuffの成功を型チェックの成功とはしていません。

テストはtmp_pathでSQLiteとCSVを分離し、本番データベースに接続しません。重複メッセージのテストでは、特定の文言の出力だけでなくデータベースへの影響を検証します。

## よくあるエラーと開発の早見表 :id=h-e379fdcaf8b8

| 問題                           | 対処                                       |
| ---------------------------- | ---------------------------------------- |
| パッケージのインストールは成功するがインポートに失敗する | 実際のインタープリターとuv runの環境を確認                 |
| --lockedで不整合が報告される           | 意図的な依存変更後は先に開発環境でロックを更新し、検証を迂回しない        |
| 新しいPythonバージョンに対応するwheelがない  | ライブラリの対応範囲を確認するか互換バージョンを選び、やみくもにコンパイルしない |
| キャッシュのハードリンクが失敗してコピーになる      | 異なるディスク上のキャッシュでよく起こる。必要に応じてlink modeを設定  |
| 非推奨の警告が出る                    | 発生元を確認して関連する更新を計画し、警告を全体で抑止しない           |

requirementsファイル、ロックファイル、ビルド依存関係にはそれぞれ役割があります。インタープリター、プラットフォーム、外部サービスも再現性に影響します。リリース時はこれらの条件も記録し、pip freezeだけを残して済ませないでください。
