# デプロイ、リリース、ロールバック :id=h-d9bab1ddeb30

学習目標：テスト済みのバージョンをユーザーへ届け、異常時にサービスを復旧します。先にコンテナー、データベースマイグレーション、CIのドキュメントを完了してください。

**適用範囲：**&#x307E;ず単一マシンのComposeで練習し、他のプラットフォームでも同じ検証原則を守ります。実際のドメイン、証明書、本番サーバーの認証情報は含みません。

## リリースする対象 :id=h-a55a1d61ff69

リリースするのは出所が明確な検証済みの成果物と設定であり、サーバーで一時的に編集したソースコードではありません。コード、イメージのdigest、設定、データベースマイグレーションの各バージョンを対応付けられるようにします。

アプリのロールバックはデータベースのロールバックとは異なります。新しいアプリが書いたデータや移行済みテーブルを、旧アプリが理解できない場合があります。

<a id="section-2"></a>

## 最小限のリリース練習 :id=h-0bf804b8b779

一貫したサンプルプロジェクトのディレクトリで、先にバックエンド、フロントエンド、Pythonのローカル検証を実行し、その後次を実行します。

```powershell
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build
docker compose ps
curl.exe --fail http://127.0.0.1:8080/actuator/health
curl.exe --fail http://127.0.0.1:8088/
```

これはローカルの練習で、buildは現在のディレクトリからビルドします。正式なリリースではCIで不変のイメージをビルドしてpushし、デプロイ環境が同じdigestを取得します。本番マシンごとに再コンパイルしないでください。

<a id="section-3"></a>

## リリース手順と完了条件 :id=h-8f9fec56193c

| 手順        | 必要な証拠                            |
| --------- | -------------------------------- |
| リリース前     | テスト成功、依存関係と設定の明確化、バックアップと復旧条件の準備 |
| データベースの拡張 | 新旧アプリの両方が理解できる互換構造               |
| 新バージョンの起動 | プロセス、ヘルスチェック、依存先への接続が正常          |
| スモークテスト   | 実際のログイン、作成、検索、権限拒否が想定どおり         |
| 観察        | エラー率、遅延、リソース使用量、業務結果が正常          |
| 完了        | バージョン、デプロイ時刻、検証結果を記録             |

ヘルスエンドポイントが証明するのは、その検証範囲だけです。ホームページの200はAPIに書き込める証明ではなく、APIを読めても権限やデータ移行が正しい証明にはなりません。

<a id="section-4"></a>

## 2つの成果物でロールバックを理解する :id=h-f818868810d5

新バージョンのデプロイ前に旧イメージのdigestと設定を記録します。明確なロールバック条件に達したら、旧イメージと互換性のある設定を戻し、再起動して同じスモークテストを実行します。

「oldタグを取得する」だけでは不十分です。タグは上書きされている場合があります。リリース記録の不変のdigestや成果物のチェックサムで元のバージョンを取得します。

データベース変更が旧アプリと互換でない場合は、新たな書き込みを止め、定めた復旧計画に従います。急いで戻すために、その間に生じたデータを無視して新しい列を削除したりデータベース全体を復元したりしてはいけません。

<a id="section-5"></a>

## 停止、接続、秘密情報 :id=h-cd660caf37b5

終了シグナルを受けたプログラムは新規タスクの受け付けを停止し、実行中のリクエストに適切な完了時間を与えます。ロードバランサーやプロキシは、旧インスタンスへの転送を止めてからインスタンスを終了します。

データベース接続、HTTPリクエスト、メッセージ受信にタイムアウトを設定します。短縮だけが最適化ではなく、まず実際の呼び出し経路を測定します。再試行は回数を制限し、安全に再試行できる操作だけに適用します。

秘密情報はデプロイ環境から注入し、フロントエンドのビルド、イメージレイヤー、ログに含めません。変更時はサーバー側アカウント、実行中のインスタンス、ロールバック先バージョンも一緒に考慮します。

<a id="section-6"></a>

## 検証と開発の早見表 :id=h-5e732a76c024

| 障害             | 優先する対応                                |
| -------------- | ------------------------------------- |
| 502が大量に発生      | インスタンス、ポート、準備状態、上流ログを確認               |
| ログインが突然失敗      | セッションストレージ、キー、Cookie、プロキシのHTTPS設定を確認  |
| 書き込み競合が増加      | 業務の並行処理と旧クライアントを観察し、バージョン検証をそのまま削除しない |
| マイグレーションが長時間待機 | DDLとロックを確認し、マイグレーションプロセスを追加起動しない      |
| データ復旧後にレコードが不足 | バックアップ時刻、増分ログ、復旧目標時点を確認               |

リリース記録と復旧練習の記録を保持します。実際に復元したことのないバックアップや未検証の旧成果物を、完成したロールバック能力として扱うことはできません。
