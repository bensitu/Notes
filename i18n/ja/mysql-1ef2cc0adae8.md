## 算術演算子 :id=h-d148ea6f7954

算術演算子は主に数学的な計算に使用します。演算子の前後にある 2 つの数値または式を結び、加算（+）、減算（-）、乗算（\*）、除算（/）、剰余（%）の演算を行います。

### 加算演算子と減算演算子 :id=h-a225cb9a62a6

```sql
SELECT 100, 100 + 0, 100 - 0, 100 + 50, 100 + 50 -30, 100 + 35.5, 100 - 35.5
FROM dual;
```

- 整数型の値と整数との加算・減算の結果は整数になります。
- 結果の型はオペランドによって決まります。35.5 のような正確な小数リテラルは通常 DECIMAL として計算されます。1e0 のような科学表記のリテラルは近似数です。すべての小数を浮動小数点数と呼ぶことはできません。
- 加算と減算の優先順位は同じで、左から右へ計算します。括弧で順序を変更できます。例えば 10 - 3 + 2 は 9、10 - (3 + 2) は 5 です。
- Java では、+ の左右のどちらかが文字列なら文字列を連結します。一方、MySQL の + は数値の加算のみを表します。数値型でなければ、まず数値への変換を試み、変換できなければ 0 として計算します。（補足：MySQL で文字列を連結するには文字列関数 CONCAT() を使います。）

### 乗算演算子と除算演算子 :id=h-b5ad3afef2d6

```sql
SELECT 100, 100 * 1, 100 * 1.0, 100 / 1.0, 100 / 2,100 + 2 * 5 / 2,100 /3, 100 DIV 0
FROM dual;
```

- 数値に整数の 1 を掛けても、整数の 1 で割っても、元の値になります。
- 1.0 は正確な小数リテラルなので、結果を一律に浮動小数点数と呼ぶことはできません。結果の型と精度はオペランドの型に関係します。
- / は通常の除算を表し、整数同士の除算でも通常は DECIMAL の結果になります。DIV は整数除算です。例えばデフォルト設定では 5 / 2 は 2.5000、5 DIV 2 は 2 です。
- 除算の結果の型と精度は、オペランドの型や div_precision_increment に左右されるため、常に小数点以下 4 桁になるとは限りません。
- 乗算と除算の優先順位は同じで、左から右へ計算します。括弧を変更すると結果が変わる場合があり、有限精度の計算では丸めの差も生じることがあります。
- SELECT では、除数が 0 のとき結果は NULL になります。警告も出るかどうかは SQL モードによります。書き込み文では厳格モードでエラーになる場合があるため、計算前に除数を確認してください。

### 剰余（余り）演算子 :id=h-fe986ee694ed

```sql
SELECT 12 % 3, 12 MOD 5
FROM dual;
```

## 比較演算子 :id=h-2711c83f8521

- 比較演算子は式の左辺と右辺のオペランドを比較します。比較結果が真なら 1、偽なら 0、それ以外は NULL を返します。
- 比較演算子は、条件に一致するレコードを返すために、SELECT クエリの条件としてよく使用されます。

### 等価演算子 :id=h-a71d32fb38a4

等価演算子（=）は、両辺の値、文字列、式が等しいかを判定し、**等しければ 1、等しくなければ 0 を返します**。
等価演算子では次の規則に従います。

1. 両辺の値、文字列、式がどちらも文字列なら、MySQL は文字列として比較します。比較結果は文字セットや照合順序などによって決まります。例えば、一部の照合順序では 'a' と 'A' が等しくなるため、単純に ANSI コードの比較と説明することはできません。
2. 両辺の値がどちらも整数なら、MySQL は整数として大小を比較します。
3. 片方が整数、もう片方が文字列なら、MySQL は文字列を数値に変換して比較します。
4. 両辺の値、文字列、式のいずれかが NULL なら、比較結果は NULL です。

**比較：** MySQL のユーザー変数には := で代入できます。SET 内では = も使用できます。UPDATE で列に代入する場合は = を使います。

```sql
SELECT 1 = 1, 1 = '1', 1 = 0, 'a' = 'a', (5 + 3) = (2 + 6), '' = NULL ,NULL = NULL
FROM dual;
```

### NULL 安全等価演算子 :id=h-eac987a15b59

NULL 安全等価演算子（<=>）は等価演算子（=）と似た働きをします。唯一の違いは、<=> が NULL の判定に使えることです。両方のオペランドが NULL なら、NULL ではなく 1 を返します。片方だけが NULL なら、NULL ではなく 0 を返します。**NULL のための演算子です。**

```sql
SELECT 1 <=> '1', 1 <=> 0, 'a' <=> 'a', (5 + 3) <=> (2 + 6), '' <=> NULL,NULL <=> NULL
FROM dual;
```

### 非等価演算子 :id=h-249204d47e48

非等価演算子（<> と !=）は、両辺の数値、文字列、式の値が異なるかを判定します。異なれば 1、等しければ 0 を返します。NULL 値の判定には使えません。片方が NULL、または両方が NULL なら、結果は NULL です。

```sql
SELECT 1 <> 1, 1 != 2, 'a' != 'b', (3+4) <> (2+6), 'a' != NULL, NULL <> NULL
FROM dual;
```

### NULL の判定 :id=h-dd237ccf382a

NULL の判定（IS NULL または ISNULL）は、値が NULL かどうかを調べます。NULL なら 1、それ以外は 0 を返します。

```sql
SELECT NULL IS NULL, ISNULL(NULL), ISNULL('a'), 1 IS NULL;
```

### 非 NULL の判定 :id=h-76a668e100a3

非 NULL の判定（IS NOT NULL）は、値が NULL でないかを調べます。NULL でなければ 1、それ以外は 0 を返します。

```sql
SELECT NULL IS NOT NULL, 'a' IS NOT NULL, 1 IS NOT NULL;
```

### 最小値を求める演算子 :id=h-2c65b36f54a3

構文は LEAST(値1, 値2, …, 値n) です。「値n」は引数リストに n 個の値があることを示します。引数が 2 個以上ある場合、その最小値を返します。

```sql
SELECT LEAST (1,0,2), LEAST('b','a','c'), LEAST(1,NULL,2);
```

引数が整数や浮動小数点数なら、LEAST はその最小値を返します。文字列なら、比較に使う照合順序で最小値を選びます。比較する値のリストに NULL が含まれると大小を判定できず、NULL を返します。

### 最大値を求める演算子 :id=h-518ce3ffc40f

構文は GREATEST(値1, 値2, …, 値n) で、n は引数リストの値の個数です。引数が 2 個以上なら最大値を返します。いずれかの引数が NULL なら、GREATEST() は NULL を返します。

```sql
SELECT GREATEST(1,0,2), GREATEST('b','a','c'), GREATEST(1,NULL,2);
```

引数が整数や浮動小数点数なら、GREATEST はその最大値を返します。文字列なら、比較に使う照合順序で最大値を選びます。比較する値のリストに NULL が含まれると大小を判定できず、NULL を返します。

### BETWEEN AND 演算子 :id=h-f45e18711dbd

BETWEEN 演算子は通常、SELECT D FROM TABLE WHERE C BETWEEN A AND B の形で使います。C が A 以上かつ B 以下なら結果は 1、それ以外は 0 です。

```sql
SELECT 1 BETWEEN 0 AND 1, 10 BETWEEN 11 AND 12, 'b' BETWEEN 'a' AND 'c';
```

### IN 演算子 :id=h-453682849768

IN 演算子は、指定した値が IN リストに含まれるかを調べ、含まれれば 1、それ以外は 0 を返します。左辺が NULL なら NULL を返します。左辺がリスト内の NULL 以外の値に一致すれば 1 を返します。一致がなく、リストに NULL が含まれる場合に限り NULL を返します。

```sql
SELECT 'a' IN ('a','b','c'), 1 IN (2,3), NULL IN ('a','b'), 'a' IN ('a', NULL);
```

### NOT IN 演算子 :id=h-d5ae5cc00d9f

NOT IN は IN の結果の論理否定です。一致がなくリストに NULL がなければ 1、一致すれば 0、一致がなくリストに NULL があれば NULL を返します。WHERE は結果が真の行だけを残すため、NOT IN のサブクエリにある NULL によって、期待した行が除外されることがあります。業務条件に合わせてサブクエリの NULL を除外するか、正しい相関条件を指定した NOT EXISTS を検討します。

```sql
SELECT 'a' NOT IN ('a','b','c'), 1 NOT IN (2,3);
```

### LIKE 演算子 :id=h-6d21aadb76b4

LIKE 演算子は主に文字列の照合に使用し、通常は **パターンマッチング** に使います。条件に一致すれば 1、それ以外は 0 を返します。値またはパターンが NULL なら、結果は NULL です。LIKE では通常、次のワイルドカードを使います。
「%」：0 文字以上の任意の文字に一致します。
「\_」：ちょうど 1 文字に一致します。

```sql
SELECT NULL LIKE 'abc', 'abc' LIKE NULL;

# See note 1 below.
SELECT name FROM peoples WHERE name LIKE '%a%';

# See note 2 below.
SELECT name FROM peoples WHERE name LIKE 'a%';

# See note 3 below.
SELECT name FROM peoples WHERE name LIKE '__a%';

# See note 4 below.
SELECT name FROM peoples WHERE name LIKE '_a_b%';
```

例の説明：

1. a を少なくとも 1 つ含む文字列を検索します。% は a の前後にある 0 文字以上の文字に一致します。
2. a で始まる値を検索します。
3. 3 文字目が a の値を検索します。
4. 2 文字目が a で、4 文字目が b の値を検索します。

### ESCAPE :id=h-93bd230563b4

% と \_ は LIKE で特別な意味を持ちます。文字そのもののパーセント記号やアンダースコアに一致させるには、ESCAPE でエスケープ文字を明示し、バックスラッシュや SQL モードへの依存を避けます。

```sql
SELECT job_id FROM jobs WHERE job_id LIKE 'IT!_%' ESCAPE '!';
SELECT '50% off' LIKE '50!% off' ESCAPE '!';
```

最初の文は IT\_ で始まる職種 ID に一致し、2 番目の文は文字そのものの % に一致します。エスケープ文字自体もエスケープする必要があります。

### REGEXP 演算子 :id=h-505b8e2ea299

REGEXP 演算子は文字列の照合に使用します。構文は次のとおりです。

```sql
expr REGEXP 匹配条件
```

expr がパターンに一致すれば 1、一致しなければ 0 を返します。expr またはパターンのいずれかが NULL なら、結果は NULL です。

REGEXP の照合では、次のパターン文字をよく使います。

1. ^ は、その後ろに指定した文字で始まる文字列に一致します。
2. $ は、その前に指定した文字で終わる文字列に一致します。
3. . は通常、改行以外の 1 文字に一致します。改行にも一致するかどうかは正規表現のオプションによります。
4. \[…] は角括弧内のいずれかの文字に一致します。例えば \[abc] は a、b、c のいずれかに一致します。文字の範囲には - を使います。\[a-z] は a から z の範囲で、大文字・小文字の扱いは照合順序や正規表現のオプションによります。\[0-9] は任意の数字に一致します。
5. *&#x20;は直前の文字の 0 回以上の繰り返しに一致します。例えば x* は任意個の x、\[0-9]*&#x20;は任意個の数字に一致します。\* 単独は任意の文字を表す有効なパターンではありません。.* が 0 文字以上の任意の文字を表します。

```sql
SELECT 'shkstart' REGEXP '^s', 'shkstart' REGEXP 't$', 'shkstart' REGEXP 'hk';
```

## 論理演算子 :id=h-fdff6803980c

論理演算子は主に式の真偽を判定します。MySQL では結果は 1、0、NULL のいずれかです。新しいコードでは標準 SQL のキーワード NOT、AND、OR を優先します。!、&&、論理 OR としての || は従来の拡張です。PIPES_AS_CONCAT が有効な場合、|| は文字列連結を表します。参考：[MySQL の論理演算子](https://dev.mysql.com/doc/refman/8.4/en/logical-operators.html)。

### 論理否定演算子 :id=h-c7fb7d3f4274

論理否定（NOT または !）は、指定した値が 0 なら 1、0 以外なら 0 を返します。
値が NULL の場合は NULL を返します。

```sql
SELECT NOT 1, NOT 0, NOT(1+1), NOT !1, NOT NULL;
```

### 論理積演算子 :id=h-57e042b1bf64

論理積（AND または &&）は、指定したすべての値が 0 以外で、どれも NULL でなければ 1 を返します。1 つ以上の値が 0 なら 0、それ以外は NULL を返します。

```sql
SELECT 1 AND -1, 0 AND 1, 0 AND NULL, 1 AND NULL;
```

### 論理和演算子 :id=h-22e39fa24091

論理和（OR または ||）は、両方の値が NULL でなく、少なくとも一方が 0 以外なら 1、それ以外は 0 を返します。一方が NULL で、他方が 0 以外なら 1、それ以外は NULL を返します。両方が NULL なら NULL を返します。

```sql
SELECT 1 OR -1, 1 OR 0, 1 OR NULL, 0 || NULL, NULL || NULL;
```

**注意：**
OR と AND は併用できますが、優先順位に注意してください。AND は OR より優先順位が高いため、先に AND の両辺を計算し、その結果を OR のオペランドと組み合わせます。

### 排他的論理和演算子 :id=h-56280a249dbc

排他的論理和（XOR）は、いずれかの値が NULL なら NULL を返します。NULL でない 2 つの値については、両方が 0、または両方が 0 以外なら 0 を返します。一方が 0 でもう一方が 0 以外なら 1 を返します。

```sql
SELECT 1 XOR -1, 1 XOR 0,0 XOR 0, 1 XOR NULL, 1 XOR 1 XOR  1, 0  XOR 0 XOR 0;
```

## ビット演算子 :id=h-9d2d2dc6b19c

ビット演算子は 2 進数に対して計算を行います。まずオペランドを 2 進数に変換し、ビット演算を行ってから、結果を 10 進数に戻します。

### ビット AND 演算子 :id=h-3f163d070321

ビット AND（&）は、指定した値の 2 進表現で、対応するビット同士の論理積を求めます。両方のビットが 1 なら結果のビットは 1、それ以外は 0 です。

```sql
SELECT 1 & 10, 20 & 30;
```

### ビット OR 演算子 :id=h-2979e915fc09

ビット OR（|）は、指定した値の 2 進表現で、対応するビット同士の論理和を求めます。一方または両方のビットが 1 なら結果のビットは 1、それ以外は 0 です。

```sql
SELECT 1 | 10, 20 | 30;
```

### ビット XOR 演算子 :id=h-23d447480e17

ビット XOR（^）は、指定した値の 2 進表現で、対応するビット同士の排他的論理和を求めます。ビットの値が異なれば結果のビットは 1、それ以外は 0 です。

```sql
SELECT 12 & 5, 12 | 5,12 ^ 5 FROM DUAL;
```

### ビット反転演算子 :id=h-84b1376be808

ビット反転（\~）は、指定した値の 2 進表現の各ビットを反転し、1 を 0、0 を 1 にします。

```sql
SELECT 10 & ~1;
```

### 右ビットシフト演算子 :id=h-f4ac7b1e039b

右ビットシフト（>>）は、指定した値の 2 進表現の全ビットを指定桁数だけ右へ移動します。右端からはみ出した下位ビットは破棄され、左側の空いた上位ビットは 0 で埋められます。

```sql
SELECT 1>>2, 4>>2;
```

### 左ビットシフト演算子 :id=h-d49fbf3f9d8b

左ビットシフト（<<）は、指定した値の 2 進表現の全ビットを指定桁数だけ左へ移動します。左端からはみ出した上位ビットは破棄され、右側の空いた下位ビットは 0 で埋められます。

```sql
SELECT 1 << 2, 4 << 2;
```
